# `<ROOM_ID>`房间设计模板

## 使用说明

- 将本文复制为对应区域目录下的`<ROOM_ID>.md`，再替换全部占位内容。
- 本模板只规定正式房间文档需要记录的信息，不批准任何房间、区域或系统机制。
- 不适用的章节明确填写“不适用”并说明原因，不得通过删除章节隐藏尚未确认的规则。
- 所有“待确定”或“待确认”内容在获得批准前不得进入对应Scene实现。
- Scene、本文档、`docs/maps/MAP.md`和对应区域`ROOM_INDEX.md`中的房间编号必须完全一致。

## 制作顺序

1. 确认地图连接、区域规则、房间批准状态和全部依赖机制。
2. 按标准Tilemap结构完成静态地形灰盒。
3. 配置静态碰撞、表面语义和相机边界。
4. 创建并独立验证缺失的通用Prefab或组件。
5. 以保持Prefab连接的Scene实例组合动态玩法对象。
6. 存在Spawner时配置出生点、Spawner和房间注册表，并验证ID、引用与安全空间。
7. 完成自动验证和房间内人工试玩。
8. 灰盒通过后再添加正式美术。

## 验收标准

- Scene、房间文档、地图和区域索引使用同一个房间ID。
- 入口、出口和相邻房间连接一致。
- 静态地形使用标准Tilemap层，动态玩法对象使用通用Prefab或组件。
- Player、MirrorClone和镜子行为没有被房间实例覆盖。
- 死亡、手动重置、MirrorClone单独死亡、重复放置和场景切换结果正确。
- 使用Spawner时，出生点ID唯一、引用有效、空间安全，并且不会重复生成或在场景切换后留下旧请求。
