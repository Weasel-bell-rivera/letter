# 解谜可玩性评估标准 v1.0

制定日期：2026-08-31。适用：W1 的机制教学、平台解谜、组合与挑战房。

本标准用于评审和排序，不批准新玩法，不覆盖现有系统文档，不改变房间状态，也不自动授权试玩、自动测试或重建。权重是针对本项目优先级制定的工作标准，并非行业公认量表；首次盲测后可以版本化校准。

## 1. 要评估的体验

好的解谜关卡让玩家经历：看懂问题 → 提出猜想 → 做出能验证猜想的操作 → 看懂结果 → 修正理解 → 有把握地完成。

可玩性不等于困难、通关时长、死亡次数、机关数量或美术精细度。必须同时问：**玩家学到了什么？为什么需要这个解法？想明白之后是否还会被执行与重复劳动阻拦？**

## 2. 从已有作品提取的原则

以下“应用”是本项目的归纳，不是原作者公布的评分体系，也不要求复制这些游戏。

| 参考 | 可核查的经验 | 在W1中的应用 |
|---|---|---|
| 《Braid》《The Witness》 | Jonathan Blow说明，每个谜题应有具体思想，理解真实关系比制造任意的“卡住再突然成功”更重要；同时避免无关干扰。[作者访谈](https://www.gamedeveloper.com/business/q-a-jonathan-blow-on-i-the-witness-i-and-the-state-of-indie-games) | 每房写一句“玩家原先以为……，后来理解……”。不能只写“开三扇门”。 |
| 《Baba Is You》 | 规则以可推动的实体文字存在，玩家能改变对象用途。[开发者介绍](https://www.hempuli.com/games/games.php?title=baba) | 借鉴“重新理解对象用途”：火球可以触发机关，门可以遮挡攻击。W1仍严格保持已批准规则，不能把临时例外当惊喜。 |
| 《Braid》 | 发行方说明其时间回溯机制，并允许卡住时先离开、之后返回。[发行方产品说明](https://www.nintendo.com/US/store/products/braid-anniversary-edition-switch/) | 衡量错误假设的试验成本、回到决策点的时间和无效重复；不据此给W1增加撤销或跳关。 |
| Valve（《Portal》开发团队）的研究方法 | 将设计视为假设，用观察、问答和行为数据验证；统计与自述各有局限。[Mike Ambinder，GDC 2009，第4、12、19、34页](https://cdn.fastly.steamstatic.com/apps/valve/2009/GDC2009_ValvesApproachToPlaytesting.pdf) | “作者能解”与“陌生玩家能理解”分别记录。完成率、耗时和玩家解释交叉核对，不能用截图或测试绿灯代替体验。 |

## 3. 先定义房间角色和完成条件

先填写：房间ID、版本、入口、前置知识、房型、本轮完成条件、允许的其他解法、明确禁止的绕过方式、失败恢复方式。

- 引入房：安全地获得一种新理解即可得高分，不要求复杂反转。
- 练习/组合房：检查已有知识是否被主动应用、是否产生新的关系。
- 精通/挑战房：可以增加规划深度，但不能把隐蔽规则或窄时间窗冒充深度。
- 节奏房：以低负担过渡为目的，不因为没有镜像谜题扣分；按角色另写评价，不与挑战房直接排行。
- 占位、纯空间/表面原型：没有批准完成条件时不出谜题总分。
- 无正式出口但有批准局部目标的原型：可评局部因果链，不能声称区域流程完成。

地图编号不是教学顺序。前置知识必须由实际可访问路径或明确的教学安排支持。

## 4. 五项门槛

门槛结果使用“通过 / 错误 / 已批准例外 / 待验证 / 不适用”，与`LEVEL_BUILDING.md`的RV检查兼容。**发现错误时不能给出“合格关卡”结论，分数不能抵消错误。缺证据不等于错误。**

| ID | 门槛 | 如何判断 |
|---|---|---|
| G1 | 解法符合权威规则 | 无房间私有例外；文档解法不能要求Player做系统明确禁止的动作。对应RV-09/12。 |
| G2 | 存在可执行的完成路径 | 从实际入口开始，包含准备、共享输入、碰撞、时序和最终状态；不能把Player和MirrorClone两条分别可走的路线当作共同解法。对应RV-03/08/09。 |
| G3 | 失败可恢复 | 死亡、回收、镜像死亡、误操作、返回入口均不形成不可恢复状态；手动重置可恢复不代表重试成本低。对应RV-01/11。 |
| G4 | 必要信息可获取 | 操作前有机会看见危险与落点；区分普通板、持续板、锁存板，以及FrozenGround和FreezingGround。不强制展示全部答案。对应RV-07/10。 |
| G5 | 声明的核心约束真实存在 | 若房间明确要求镜像或机关，检查直接走、直接跳、提前回收、分次操作、返回入口等反例。合法的创造性多解不自动算逃课；只否决破坏声明目标的绕过。对应RV-05/08/09。 |

## 5. 100分量表

每项先给0～4级，再按`权重 × 等级 / 4`换算。只用整数等级，允许结果出现小数，但小数只是算术，不代表测量精度。每项必须附证据、主要扣分理由和一个可复测问题。

| 项 | 权重 | 0级 | 2级 | 4级 |
|---|---:|---|---|---|
| A 核心理解 | 20 | 没有明确思想，纯碰运气/跑流程 | 有可描述的规则应用，但停留在直接使用 | 出现清楚、可迁移的新理解；引入房可用一个简单规则达成 |
| B 推理公平 | 15 | 解法依赖矛盾规则或不可知条件 | 线索支持方向，但有关键假设只能猜 | 从可获取信息能建立假设，失败能排除假设，解后能解释 |
| C 机制与目标关系 | 15 | 声明必需的机制完全不影响完成 | 机制有帮助，但必要性或替代解边界不清 | 目标、约束和操作形成必要关系，合理多解边界明确 |
| D 因果反馈 | 10 | 无法判断操作是否生效或失败原因 | 起因与结果可辨，但中间状态含糊 | 目标、可操作对象、状态、作用结果和失败原因均可读 |
| E 执行容错 | 10 | 明白解法仍依赖不稳定输入/极窄窗口 | 可重复完成，但同步、跳跃或等待负担较大 | 操作稳定，符合房型；难度主要来自决策，窗口有合理余量 |
| F 重试成本 | 10 | 无法恢复或重复惩罚严重 | 能恢复，但重跑和重新等待明显 | 快速回到有意义决策点；长期和临时状态恢复符合规则 |
| G 教学与节奏 | 10 | 必需知识无来源，负担与定位相反 | 局部顺序合理，但有突增或长重复段 | 实际访问路径支持前置知识，观察、练习、变化与休息配置有效 |
| H 独特性与精简 | 10 | 相邻内容只换数量/外观 | 有局部变化，但可删部分重复内容 | 每段有独立认知作用，少量元素产生清楚的新关系 |

1级：比0级有所改善，但存在主要缺陷。3级：基本达到4级，仍有具体不足或待核查的反例。

### 证据与分数的表示

- **D：设计证据**。文档、规则、因果链，只支持“设计预评分”。
- **S：静态实现证据**。当前Scene/Prefab/代码与可复算的几何、配置；不支持完整可解性结论。
- **R：运行证据**。指定版本、入口、初态、输入序列和录屏/日志；只支持实际执行的路径。
- **H：陌生玩家证据**。未看解法的目标玩家行为和复述；用于判断是否理解、是否有趣。
- **U：未知**。缺乏证据；不是0分，不用默认中间分补齐。

完整总分需要八项都有相应证据，G1～G5没有错误，并附未决风险。发布/验收另服从项目规则。

第一轮静态评审只对A/B/C/D/H提供设计预评分，合计最高70分，记作“设计预评分：x/70；E/F/G共30分待验证”。**不除以70再伪装成100分，不把它称为体验分，也不视为实际总分的下界。** 即使A/B/C/D/H满分，运行或盲测也可能推翻判断。

规则冲突房先列门槛错误，暂停总分；信息不足的房间只给已知分项。设计证据越少只是置信度越低，不自动判定游戏越差。不同房型、不同证据等级不直接排名，不把几分差解释为客观胜负。美术评分（含LIMBO基准）不进入本量表。

## 6. 固定审查步骤

1. 锁定当前工作区版本、Scene哈希和相关Prefab/参数；保留已有修改。旧Builder和旧截图仅作历史参考。
2. 写出完成条件和“一句话理解”，列出先备知识；从每个已实现入口分别检查。
3. 用表列出各阶段：Player位置/动作、MirrorClone位置/动作、门板敌人状态、完成这一阶段的依据。
4. 检查五种反例：不放镜；不操作目标机关；直接跳/从下方绕；提前回收/镜像死亡；从另一入口进入。只读推演不足的标为候选反例。
5. 计算相关空间或时序预算：角色0.8×1.8、可靠普通跳距3.5、通道净空、板持续时间与跑门距离等，以当前权威文档与参数为准。理论距离和`距离/速度`不证明可解。
6. 分开记录技术门槛、认知质量、执行负担与恢复成本；提出优先级最高的局部修改方向，不自动改机制或场景。
7. 按授权补运行/盲测；未经授权的耗时操作不执行。一个截图、一次成功或一组测试通过均不等于房间已验收。

## 7. 后续盲测方案（建议，未自动授权）

第一轮可邀请5名未看过解法的目标玩家，作为定性问题发现样本，不用它宣称总体完成率；建议分别记录平台操作经验。每人选3～4房、约20～30分钟。核心关卡改动后应使用新玩家，避免把记住答案误当教学改善。

观察者先不给提示，不要求高压跳跃时持续口述。玩家愿意求助时记录时刻；提示逐级提供“注意哪个对象→哪条关系→具体行动”，分别标记，不能算无提示完成。

| 记录项 | 操作定义 | 解释边界 |
|---|---|---|
| 目标识别 | 玩家第一次准确说出要改变什么状态的时刻 | 耗时长可能是引导问题，不一定是谜题深 |
| 理解时刻 | 玩家提出正确关系，并能预测下一次操作结果 | 不能用首次通关时刻代替 |
| 无提示完成 | 单独记录人数/有效样本数、退出与超时者 | 小样本不报“真实完成概率”；中途退出不能删掉 |
| 理解后失败 | 已说清方案后，仍因跳跃/同步/时序失败的次数与原因 | 区分操作负担与尚未真正理解 |
| 重试时间 | 从失败到能再次测试同一假设所需时间 | 包括复位、重跑、重新摆位和等待周期 |
| 重复劳动占比 | 无新信息的重跑/等候时间占该次游玩时间 | 排除有意义的观察和主动试验 |
| 迁移 | 换一个小布局后，能否解释并应用同一关系 | 不是重复原关证明记忆 |
| 主观体验 | 结束后分别询问清晰度、满足感、挫败感、继续意愿（1～5） | 不只问“好不好玩”，也不引导玩家称赞 |

首轮工作警戒线可暂设：5人中2人出现同一误解就优先检查；理解后连续失败3次就检查执行负担；反复出现重试超过15秒或无信息重复超过约三分之一就检查恢复路径。**这些是排查触发器，不是行业阈值或自动不及格线**；挑战房需结合已批准定位解释。
