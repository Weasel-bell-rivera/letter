- 运行时创建敌人时，出生点、Spawner、房间注册、空间安全、重置和场景卸载规则见`docs/systems/ENEMY_SPAWN_SYSTEM.md`。

## 已批准敌人类型

### 通用冻结地面资格

- 所有Enemy类型都能累积`FreezingGround`效果；关卡可以通过路线和布局避免特定Enemy实际接触，但不得在Enemy类型中硬编码免疫。
- Collider首次接触`FreezingGround`时锁定目标格并开始减速与冻结累积；离开后在空中保持冻结量，落到普通安全地面逐渐恢复。
- 完全冻结时停止当前AI阶段和运动，清空速度并关闭伤害。原本不是安全踏板的Enemy不会仅因冻结自动变成可站立平台。
- 通用`FreezingGround`冻结与可冻结地面巡逻敌人踩上`FrozenGround`后的专用平台化冻结是两个入口；后者继续沿用本文件既有规则。
- 手动重置、Player死亡重置和场景切换恢复Enemy初始活动状态并清除冻结量及目标格；MirrorClone死亡或镜子回收不影响Enemy冻结进度。

### 可冻结地面巡逻敌人

- 沿房间明确配置的固定水平范围来回巡逻。
- 到达巡逻端点后短暂停顿并转向。
- 不随机改变速度、方向或停顿时间。
- 不主动追踪Player或MirrorClone。
- 不跳跃、不飞行、不攀墙，也不主动走下平台边缘。
- 脚部稳定接触`FrozenGround`表面后在首次接触格内逐渐冻结，并在格中心完全冻结。
- 冻结后转化为Player和MirrorClone都能站立的安全平台。

### 风区逐风鳐

- 在固定守卫点感知一定世界距离内且无遮挡的Player或MirrorClone。
- 选择距离最近的合格角色，记录其位置并进行可预判的直线冲刺。
- 命中Player时触发完整房间重置；命中MirrorClone时只执行镜像死亡联动。
- 攻击后在新位置喘息，再缓慢返回守卫点，形成Player可利用的通过窗口。
- 不自由追踪、不随机游荡、不产生风力，也不依赖其他风区机制。
- 详细状态、平局、遮挡、锁定、表现和房间使用规则以`docs/systems/WIND_RAY_ENEMY.md`为准。

### 风区殉风鳐

- 与逐风鳐共享感知、目标选择、预警、直线冲刺、统一数值和视觉结构。
- 成功命中MirrorClone后，镜像死亡、镜子回收，殉风鳐在本次房间尝试内被击败。
- 命中Player仍触发完整房间重置，殉风鳐随重置恢复。
- 因死亡与重置结果不同，殉风鳐属于独立敌人原型和独立基础Prefab，不使用Unity Prefab Variant。
- 完整规则见`docs/systems/WIND_RAY_ENEMY.md`。

### 竖直墙面巡逻敌人

- 沿房间实例显式配置的固定竖直范围上下巡逻，路径而不是墙壁Collider形状决定正常移动范围。
- 每个固定物理步同时验证身体侧面的有效静态墙面；墙面是攀附资格，不自动生成或延长巡逻路径。
- 到达上下端点后短暂停顿并反向，不随机改变速度、方向或停顿时间。
- 不追踪Player或MirrorClone，不跳跃、不飞行、不转过墙角，也不从墙面移动到地面或天花板。
- 接触Player或MirrorClone时沿用通用活动敌人的伤害与生命周期规则。
- 首版不能冻结、不能被推动、不能触发压力板，也不能作为镜子放置表面。
- 当前状态：行为规则、统一数值和通用Prefab均已实现。

### 火区投火者

- 固定在房间显式配置的位置，在世界空间`12 × 1.5 units`水平攻击带内感知无遮挡的Player与MirrorClone。
- 两者同时合格时选择水平距离更近者，平局选择Player；蓄力开始后只锁定左或右方向，不继续追踪。
- 蓄力`0.6 s`后生成一枚速度`8 units/s`的独立水平火球，发射后冷却`1.4 s`；同一敌人同时最多保有一枚火球。
- 火球命中实体阻挡后销毁；命中Player触发完整房间重置，命中MirrorClone只执行镜像死亡与镜子回收。
- 火球离开相机边界`1 unit`或存活`2 s`后销毁，不产生爆炸、残留火焰或地形变化。
- 敌人与火球不破坏镜子、不触发机关、不推动动态对象；攻击全程不显示红色小叉或落点标记。
- 完整规则与首版数值见`docs/systems/HORIZONTAL_FIREBALL_ENEMY_PROPOSAL.md`。首次正式教学房为`FIRE_002`，`FIRE_009`用于后续巩固。

### 固定投火兵

- 固定站在Scene配置的地面守卫点，不巡逻、不追逐、不跳跃。
- 在`7 units`内按距离和视线选择最近的Player或MirrorClone，平局稳定选择Player。
- 进入预警时锁定目标世界位置，`0.8 s`后投出不追踪的确定性弧线火球。
- 命中Player触发完整房间重置；命中MirrorClone只执行镜像死亡联动。
- Cooldown期间不重新索敌，所有在途火球在完整房间重置时清除。
- 不绘制运行时探测圆；详细状态、弹道、Prefab、重置和数值以`docs/systems/GROUND_FIRE_THROWER_ENEMY.md`为准。

## 敌人原型与Prefab Variant

### 敌人原型判定

敌人原型由核心玩法机制定义，不根据名称、所属区域、Sprite或动画是否相似判断。满足以下全部条件的多个敌人版本，属于同一敌人原型：

- 使用相同的核心控制器和状态机。
- 使用相同的移动模型、攻击流程和目标选择规则。
- 使用相同的实体碰撞、伤害、死亡、重置和场景切换规则。
- Prefab根节点、核心玩法组件和必要子物体结构一致。
- 版本差异可以完全通过已批准的序列化参数、共享配置资产和表现资源表达。
- 不需要删除、替换或禁用基础Prefab的核心玩法组件。

动画或移动外观看起来相似，不足以判定为同一原型。地面巡逻、竖直墙面巡逻、飞行冲刺和定点投射等不同运动或攻击模型分别属于独立原型。

### Prefab Variant使用规则

同一敌人原型需要制作两个或更多可跨房间复用的稳定版本时，新增版本必须以该原型的基础Prefab创建`Prefab Variant`，不得复制基础Prefab形成失去继承关系的独立资产。Variant继承的是GameObject层级、组件和序列化配置，不表示具体敌人控制器之间必须建立C#类继承。

Prefab Variant可以覆盖：

- Sprite、Animator、材质、粒子、音效及不改变反馈含义的表现参数。
- 原型文档明确允许覆盖的速度、等待时间、感知范围或其他玩法参数。
- 不改变玩法轮廓、碰撞资格和交互结果的视觉偏移。
- 已批准的区域主题表现。

Prefab Variant不得：

- 替换核心控制器或改变状态机。
- 删除、禁用或绕过伤害、重置和场景生命周期组件。
- 私自改变Player、MirrorClone、镜子、门、压力板或表面语义的交互规则。
- 私自增加冻结、飞行、攀墙、投射、镜子破坏或其他玩法资格。
- 通过覆盖Collider改变原型的玩法轮廓、站立资格或安全空间要求。
- 改变死亡、房间重置、场景切换或长期存档规则。

如果一个版本需要违反上述任一限制，必须定义为新的敌人原型和独立基础Prefab，并先更新本文、对应敌人专项文档、Prefab目录及相关测试。

房间专用的位置、巡逻端点、初始方向、守卫点和其他允许的实例参数直接配置在Scene中的Prefab实例上，不为单个房间创建Variant。只有会被多个房间复用且差异稳定的版本才创建Variant。

当前`FreezablePatrolEnemy2D`、`VerticalWallPatrolEnemy2D`、`WindRayEnemy2D`、`HorizontalFireballEnemy2D`和`GroundFireThrowerEnemy2D`分别属于独立敌人原型，不得互相作为Prefab Variant。活动与冻结仍是`FreezablePatrolEnemy2D`同一实例的运行时状态变化，不创建冻结Variant。

## 竖直墙面巡逻规则

### 路径与配置

每个房间实例必须显式配置：

- 初始位置，作为本地路径锚点。
- 攀附墙面位于敌人左侧还是右侧。
- 下巡逻端点和上巡逻端点，使用相对路径锚点的本地竖直偏移。
- 初始移动方向。
- 移动速度。
- 端点等待时间。

首版上下端点必须具有相同的本地`X`，且下端点严格低于上端点。敌人Transform保持无旋转和单位缩放；房间不能通过旋转Prefab把竖直巡逻改成水平或斜向巡逻。Prefab资产不得包含正式房间世界坐标、房间编号或路线。

### 运动权威与物理

- 显式配置的上下端点是正常运动范围的唯一权威来源；不得通过射线沿墙搜索、Tile边界、Collider边界或对象名称自动推导端点。
- 根对象使用Kinematic `Rigidbody2D`，关闭重力和物理旋转，启用插值与连续碰撞检测。
- 玩法位移只在`FixedUpdate`中通过`Rigidbody2D.MovePosition`执行，不直接逐帧写Transform。
- 敌人保持固定世界`X`，以固定速度朝当前端点移动；到达端点时精确夹紧到端点，速度归零，等待配置时间后反向。
- 墙面探测、端点判断、等待计时和伤害资格不得依赖渲染帧率或随机数。

### 墙面攀附验证

- 敌人从靠墙一侧的`WallProbe`朝配置墙面方向进行短距离BoxCast或等价形状查询。
- 首版只有带安全、静态`StaticSolid`表面语义的连续竖直墙面提供攀附资格。
- `SpecialMirrorWall`、`FrozenGround`、`Hazard`、`DynamicSurface`、`Conveyor`、门、移动平台和仅有墙面外观的装饰均不提供攀附资格。
- 查询不得根据Tile、Sprite、GameObject、Tilemap或房间名称判断墙面。
- 初始位置没有有效墙面、端点顺序错误、路径不竖直或配置数值非法时，属于配置错误：敌人停止运动、关闭伤害并报告错误。
- 正式房间必须验证整个上下路径旁存在连续有效墙面。运行时若探测到意外墙面中断，敌人立即停止，在端点等待时长后反向，并只报告一次配置警告；不得离墙悬空继续巡逻。
- 首版不跨越墙面缺口，不连接相邻Collider形成自动路线，也不绕过内角或外角。需要沿复杂轮廓爬行时，应设计独立的表面路径敌人，而不是扩展房间实例规则。

### 碰撞、伤害与机关

- 敌人使用与可见身体轮廓一致的非Trigger实体Collider，并使用独立Damage Trigger结算接触伤害。
- 接触Player时触发完整房间死亡重置；接触MirrorClone时只执行镜像死亡联动，Player和房间不整体重置。
- 敌人不能持续挤压、推动或夹住角色；房间必须在整条竖直路径周围预留完整角色空间。
- 敌人不能被Player或MirrorClone推动，不能触发压力板，不能拾取道具，也不破坏镜子。
- 敌人不是安全平台，Player和MirrorClone不能把它当作站立或攀附表面。
- 首版路线不得穿过门、移动门、移动平台、传送带或其他动态对象的运行范围。

### 重置与场景切换

- 手动重置或Player死亡重置时，恢复初始位置、初始方向、巡逻阶段和端点等待计时，清空线速度、角速度、墙面接触缓存和伤害占用。
- MirrorClone单独死亡、镜子回收或镜子被破坏时不重置敌人的位置、方向或等待计时。
- 重新进入房间时按实例初始配置创建；场景切换不携带位置、方向、等待计时或墙面接触状态。
- 所有状态属于`RoomAttemptState`，不写入长期存档。

### 统一数值与视觉轮廓（已确定）

| 参数 | 统一值 |
|---|---|
| 默认下端点 | 路径锚点下方`2 units` |
| 默认上端点 | 路径锚点上方`2 units` |
| 默认移动速度 | `1.5 units/s` |
| 房间实例速度范围 | `0.5～3.0 units/s` |
| 默认端点等待 | `0.3 s` |
| 房间实例等待范围 | `0～1.0 s` |
| 默认墙面侧别 | 左侧 |
| 默认初始方向 | 向上 |
| Sprite导入 | `128 PPU`、Point Filter、Full Rect、不生成物理轮廓 |
| 实体Collider | `0.72 × 0.90 units`，中心向墙偏移`0.10 unit` |
| Damage Trigger | `0.82 × 0.98 units`，中心向墙偏移`0.10 unit` |
| 墙面探测距离 | `0.16 unit` |
| 墙面法线阈值 | 墙面法线与敌人离墙方向点积不小于`0.65` |

## 可冻结地面巡逻敌人状态模型

```text
Active
  |
  | 脚部稳定接触FrozenGround
  v
Freezing
  |
  | 抵达首次接触格中心
  v
Frozen
```

手动重置、Player死亡重置或重新进入房间时，敌人恢复为房间配置的`Active`初始状态。MirrorClone单独死亡不重置敌人。

### `Active`

活动状态下：

- 敌人按房间实例配置的巡逻范围移动。
- 敌人对Player和MirrorClone具有伤害。
- 敌人使用正常实体碰撞，但不能持续挤压、推动或夹住角色。
- 敌人不能触发压力板。
- 敌人不能推动或破坏镜子。
- 敌人不是镜子放置表面。

### `Frozen`

冻结状态下：

- 立即停止巡逻并清空线速度和角速度。
- 禁用全部伤害判定。
- 保留与冻结视觉轮廓一致的实体Collider。
- Player和MirrorClone都能稳定站在其顶部。
- 本次房间尝试中不自动解冻。
- 不能被推动、不能触发压力板，也不能作为镜子放置表面。
- 不写入长期存档。

冻结不得通过销毁活动敌人并生成另一个Prefab实现。活动和冻结必须是同一个敌人实例的确定性状态变化。

### `Freezing`

- 首次脚部稳定接触`FrozenGround`时锁定对应的一格寒冰及其世界空间中心。
- 敌人保持进入寒冰时的行进方向，在该格内连续降低到最低`25%`巡逻速度；不会因减速在格中心前转向。
- 冻结视觉进度按进入位置到格中心的行进比例连续增加；此阶段仍属于危险敌人并保持伤害。
- 抵达或越过格中心的固定物理帧，将世界X吸附到格中心并进入`Frozen`；不修改世界Y或碰撞轮廓。
- 手动重置、Player死亡重置或场景切换清除目标格、冻结进度和减速。

## 巡逻规则

敌人的巡逻范围由房间实例显式配置：

- 初始位置
- 初始方向
- 左巡逻端点
- 右巡逻端点
- 移动速度
- 端点等待时间

敌人到达任一端点后停止、等待配置时间、转向并继续巡逻。敌人被墙阻挡时停止并转向，不得持续向墙内施力或持续挤压角色。

首版巡逻范围必须位于连续、可站立的地面上。敌人不得根据房间编号、GameObject名称、Tile名称或Sprite名称确定路线或行为。

## 伤害与镜像交互

活动敌人接触Player时：

- Player进入死亡重置流程。
- MirrorClone立即消失并清理全部Trigger、压力板和事件占用。
- 已解锁的镜子回到Player手中。
- 房间按`docs/systems/RESET_SYSTEM.md`的统一顺序恢复。

活动敌人接触MirrorClone时：

- MirrorClone死亡并立即清理全部Trigger、压力板和事件占用。
- 镜子自动回到Player手中。
- Player不死亡，房间不执行整体重置。
- 敌人继续保持当前活动状态和巡逻阶段。

冻结敌人不伤害Player或MirrorClone。敌人默认不破坏镜子；以后只有明确批准的特殊敌人能力才能改变该规则。

## 冻结资格与触发

只有明确实现`Freezable`资格的敌人才能进入冻结状态。冻结触发必须同时满足：

1. 敌人当前处于`Active`状态。
2. 敌人的落地检测确认其稳定着地。
3. 敌人脚部检测到`FrozenGround`表面语义，并能锁定首次接触格中心。
4. 当前没有进行死亡、重置或场景切换。

以下情况不触发冻结：

- 身体侧面接触寒冰墙壁。
- 头部接触寒冰天花板。
- 接触只有冰雪外观的背景或装饰。
- 接触普通`StaticSolid`表面。
- 敌人已经处于`Frozen`状态。

冻结结算不得依赖Tile名称、Sprite名称、Tilemap名称、GameObject名称或房间编号。Tilemap表面使用其Grid单元中心；非Tilemap原型表面使用同一世界一单位网格约定。

## 冻结敌人的平台规则

- Player和MirrorClone都可以站在冻结敌人顶部。
- 冻结敌人的可见顶部与实体Collider顶部必须一致。
- 角色站上去时，敌人不能移动、旋转、倾倒或被推出。
- 冻结敌人位于移动平台上时，应稳定随平台移动。
- 冻结敌人仍属于动态表面，不能放置镜子。
- 首版不允许多个冻结敌人互相堆叠。
- 首版不处理敌人在半空中被冻结。
- 首版不把冻结敌人放入移动门的关闭路径。

## 与门的交互

- 活动敌人可以通过已经完全开启且路线明确允许的普通门。
- 门关闭路径被活动或冻结敌人占用时必须暂停关闭，不能压死、推出、穿过敌人或强制改变其状态。
- 门等待敌人离开期间保持开启和无阻挡，不改变敌人的巡逻、伤害或冻结结算。
- 房间必须在门与目标寒冰地面之间保留足够距离，使敌人在完全离开门的关闭范围后才可能冻结。
- 活动敌人被已经关闭的门阻挡时按墙壁处理：停止并转向，不持续向门内施力。
- 门与敌人的防夹规则见`docs/systems/DOOR_SYSTEM.md`。

## 重置与场景切换

敌人参与统一房间重置。手动重置或Player死亡重置时：

- 恢复初始位置和初始方向。
- 恢复初始巡逻阶段和端点等待计时。
- 清空线速度、角速度和接触状态。
- 恢复`Active`状态、活动视觉和伤害判定。
- 清除冻结视觉、冻结平台状态以及角色站立引用。

MirrorClone单独死亡不重置敌人。场景切换时不携带敌人位置、巡逻阶段、接触引用或冻结状态。竖直墙面巡逻敌人同时清除墙面接触缓存，并恢复实例配置的路径锚点、初始方向和巡逻阶段。

投火者在手动重置、Player死亡重置或重新进入房间时恢复初始位置、初始朝向和`Watching`状态，清除目标、蓄力、冷却与全部在途火球。MirrorClone单独死亡或镜子回收不重置投火者，也不取消已经锁定方向的发射。场景切换不得保留旧房间火球或延迟生成请求。

逐风鳐在手动重置、Player死亡重置或重新进入房间时恢复初始守卫点和`Guarding`状态，并清空目标、锁定点、速度与全部阶段计时。MirrorClone单独死亡或镜子主动回收不重置逐风鳐。场景切换不携带其位置、状态、目标或计时。

投火兵在手动重置、Player死亡重置或重新进入房间时恢复初始守卫点、初始朝向和`Guarding`状态，并清空目标、锁定点、阶段计时与全部在途火球。MirrorClone单独死亡或镜子主动回收不重置投火兵；已经锁定的攻击继续指向原世界位置。场景切换不携带其状态或火球。

## 存档

地面巡逻敌人的位置、方向、巡逻阶段和冻结状态，竖直墙面巡逻敌人的位置、方向、等待计时和墙面接触状态，逐风鳐的位置、目标和攻击阶段，以及投火兵的目标、阶段计时与在途火球，都属于`RoomAttemptState`，不写入长期存档。

## 验收标准

- 敌人只在配置的巡逻范围内稳定来回移动。
- 巡逻结果不依赖帧率或随机数。
- 敌人脚部稳定接触`FrozenGround`后只启动一次冻结过程，并在首次接触格中心完全冻结。
- 敌人侧面或头部接触寒冰不会冻结。
- 活动敌人分别按规则伤害Player和MirrorClone。
- 冻结敌人停止伤害，并能被Player和MirrorClone稳定踩踏。
- 冻结敌人和活动敌人都不能作为镜子放置表面。
- MirrorClone单独死亡不会重置敌人。
- Player死亡和手动重置会完整恢复敌人初始状态。
- 场景切换不会携带敌人冻结状态。
- 竖直墙面巡逻敌人只在配置的垂直端点间移动，持续验证`StaticSolid`墙面，并在意外失去墙面时停止后反向。
- 竖直墙面巡逻敌人不会绕角、跨越缺口、攀附特殊镜墙或把墙面Collider边界当作自动路线。
- 竖直墙面巡逻敌人接触Player和MirrorClone时分别执行正确的死亡流程，重置和场景切换恢复完整初始状态。
- 逐风鳐只选择感知距离内且无遮挡的最近Player或MirrorClone，并在锁定后保持同一锁定点。
- 逐风鳐命中MirrorClone不会触发房间整体重置，命中Player会触发完整死亡重置。
- 逐风鳐的喘息与返回阶段不会获取新目标，重置和场景切换不会留下攻击状态。
- 投火兵只锁定距离内且无遮挡的最近Player或MirrorClone，锁定点不随目标移动或回收改变。
- 投火兵的火球不追踪；命中双方分别进入正确生命周期，完整重置不会留下火球或冷却状态。
