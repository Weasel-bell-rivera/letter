# 门与压力板系统

## 压力板

- PressurePlate采用持续占用逻辑：至少一个满足条件的对象站在上面时保持激活，对象全部离开后恢复未激活。
- 允许Player、MirrorClone及显式具有PushableCrate2D的箱子触发，其他动态物体不能触发。
- 踩踏必须完整站上去：以角色主物理Collider为准，其沿压力板宽度方向的完整投影必须位于Trigger左右边界内，脚底必须位于Trigger厚度范围内，并通过角色自身落地检测。边界只允许`0.001`板局部单位的浮点容差；擦边、半身悬出、侧碰、从下方顶到或空中掠过不激活。
- Player与MirrorClone采用同一规则；角色局部上方向必须与板面上方向一致。已经激活后只要不再满足完整踩踏条件就解除该角色占用，多角色仍按至少一个有效占用结算；永久锁存结果保持原规则。
- 镜像消失或死亡时必须立即从压力板占用列表移除。
- 压力板必须提供清晰的按下、保持和弹起反馈。
- 有效踩踏后，按钮视觉沿板面向下压入`0.06 units`，约`0.10秒`完成；持续踩住时保持按下，释放后约`0.14秒`弹回。使用平滑过渡，按到底时显示按下Sprite；不能只用瞬间变色或换图表示踩踏。动画只作用于视觉子对象，不移动Trigger或延迟开关逻辑。永久锁存后保持按下，普通重置立即恢复初始表现。

### 压力板激活模式（已确定）

`PressurePlate2D`具有显式实例模式，默认值始终为`Occupancy`：

- `Occupancy`：沿用地面持续占用规则；允许Player、MirrorClone及可推动箱子触发，火球与其他动态物体无效。
- `FireballLatch`：允许把同一通用压力板Prefab安装在墙面；Player、MirrorClone和普通动态物体接触无效，只有`HorizontalFireballProjectile2D`命中才能激活。
- `FireballLatch`命中一次后立即锁存激活，对应门持续开启；火球在命中同一物理步销毁。
- 手动重置、Player死亡重置、离开并重新进入房间时，`FireballLatch`恢复未激活，对应普通门恢复房间初始状态。
- MirrorClone死亡或镜子回收不解除已经激活的`FireballLatch`。
- 压力板必须通过序列化模式判断触发规则，不得根据墙面位置、旋转、对象名、Sprite或房间编号推断。
- 墙面实例必须具有清楚的未激活、命中和已激活表现；旋转只改变安装姿态，不改变Trigger边界和规则。

## 门

- 门由一个或多个压力板或Trigger控制。
- 单压力板控制时，压力板激活则开门，压力板释放则关门。
- `FireballLatch`压力板激活时，普通门以锁存开启表现保持开启，直到统一房间重置恢复关闭。
- 多压力板控制支持AND和OR配置，默认使用AND。
- 房间文档必须明确每扇门的控制源、逻辑模式和初始状态。
- 风区风力涡轮属于已批准的持续Trigger控制源；涡轮控制的普通门不得同时配置压力板或永久锁存控制源，完整风信号规则见`docs/systems/WIND_ENVIRONMENT_SYSTEM.md`。

### 控制源唯一性（已确定）

- 门的逻辑目标状态只能由房间中明确配置的开关控制源（压力板或已批准的Trigger）、永久锁存状态以及统一重置初始化流程决定。
- Player、MirrorClone、敌人或其他动态对象与门体的碰撞、接触和重叠检测都不是开门信号，不得改变门的逻辑目标状态、视觉状态或锁存状态。
- 已完全关闭的门被Player、MirrorClone或敌人从外侧碰到时，必须继续保持关闭表现和实体阻挡；接触不得使门开启、变色或禁用Collider。
- 防夹检测只负责延迟执行已经收到的关闭命令，不是门的控制源，也不能生成开启命令。
- 具体房间可以限制哪些对象能够到达开关，但不得把“对象碰门”作为任何门的隐藏控制方式。

## 永久锁存双压力板门控组（已确定）

永久锁存双压力板门不是三个独立机关，而是一个完整的门控机关组。每组包含一扇门、两块压力板和一个稳定且全游戏唯一的`DoorGroupId`；具体房间文档必须记录组ID、门ID、两块压力板ID、初始状态和空间位置。

锁存前按两块压力板的激活数量结算：

| 激活的压力板数量 | 门状态 | 压力板状态 |
|---:|---|---|
| 0 | 关闭 | 两块均弹起 |
| 1 | 临时开启；该压力板释放且另一块未激活后恢复关闭 | 被占用的压力板按下 |
| 2 | 机关组立即进入永久锁存状态 | 两块压力板永久保持按下 |

- Player、MirrorClone和可推动箱子都可以触发压力板；其他动态物体不能触发。
- 每块压力板只输出“激活”或“未激活”状态。同一块压力板上存在多个有效对象时仍只计为一块压力板激活；直到最后一个有效对象离开才恢复未激活。
- “两块同时激活”是指在同一次物理状态结算中，两块压力板都处于激活状态。可以先持续踩住一块，再踩下另一块，不要求两个对象在同一帧进入。
- 每个物理状态结算先更新两块压力板的占用状态，再统一结算机关组状态；不得让Trigger回调顺序影响锁存结果。
- 锁存发生后，门永久保持完全开启，两块压力板永久保持按下；后续对象离开、MirrorClone死亡或消失、镜子回收或被破坏都不能解除锁存。
- 锁存状态跨手动重置、玩家死亡、房间切换、重新进入房间、退出游戏和存档读取保留，只有开始新存档才清除。
- 锁存时必须立即把`DoorGroupId`提交给统一存档服务；Scene对象不得直接写入存档文件。
- 读取到已锁存的`DoorGroupId`时，机关组直接初始化为门完全开启、两块压力板保持按下的状态，不重播首次锁存流程。
- 即使机关组已经锁存，压力板仍必须清理MirrorClone等对象留下的占用引用，但占用变化不再改变门或压力板的锁存表现。
- 临时开启与永久锁存必须提供可区分的视觉和声音反馈，玩家应能判断机关是否已经永久完成。
- 该规则必须由通用门控组件实现，不得写死在具体房间脚本中。
- 压力板与门之间不绘制实体连线。因果关系通过压力板按下状态、门的开启状态、锁存色调、声音以及关卡空间布局表达。

## 防夹安全

- 防夹只在门原本处于开启状态，并且已配置控制源随后请求关闭时生效。
- 收到关闭请求后，门的逻辑目标状态已经是关闭；若Player、MirrorClone、可推动箱子、活动敌人、冻结敌人或逐风鳐实际占用门的关闭路径，则暂缓应用关闭表现与实体阻挡。
- 对象离开后，门继续完成同一次关闭命令；防夹等待不得把逻辑目标状态改回开启。
- 已完全关闭的门不运行“受阻则保持开启”的分支。对象从门外侧接触关闭门的边界不算占用关闭路径，不能触发防夹。
- 门不得压死、推出、穿过或永久困住角色或敌人。
- 门在关闭过渡被占用而等待期间保持开启表现和无阻挡状态；这只是关闭命令的物理执行延迟，不代表控制源重新请求开启，也不改变敌人的活动、冻结、目标、攻击阶段或伤害状态。
- 房间设计必须把敌人的目标冻结位置放在门关闭范围之外，避免冻结敌人永久占用门路径。
- 关闭的门阻挡逐风鳐的感知和冲刺；逐风鳐返回守卫点时被关闭的门阻挡则原地等待，门重新开启后继续返回。
- 房间重置严格遵循 `docs/systems/RESET_SYSTEM.md` 的统一执行顺序。

## 几何与表现（已确定）

- 通用门由上下两张状态图组成，每张图保持一个标准`1 unit`地形格的纵向比例，整扇门固定为两个格子高，不得为填满门洞拉伸Sprite或Collider。
- 门的标准实体Collider为`1 × 2 units`，横向完整占据一个标准地形格并与两格门体对齐；房间不得通过实例覆盖改变门宽，或把门改成更高的隐藏阻挡。
- 标准Grid原点和Tile Anchor均未被房间覆盖时，竖直门根节点必须落在`X = 整数 + 0.5`、`Y = 整数`的门洞中心；根节点旋转保持`0°`、缩放保持`(1,1,1)`。若房间使用经过批准的非默认Grid变换，必须由Grid的显式变换计算门洞中心，不得手调近似坐标。
- 已明确设计为地板舱门或天花板门的实例允许把同一通用门整体旋转`90°`安装。旋转后的标准实体范围固定为`2 × 1 units`，必须完整占据两个连续地形格形成的水平缺口；门根节点、Collider中心和缺口中心一致，缩放仍保持`(1,1,1)`，不得用缩放改变门宽或厚度。
- 水平门关闭时可以作为缺口的实体封闭面，但不得被声明为镜子放置表面或普通静态地面；打开后其完整Collider必须禁用，缺口及其后的出口Trigger内不得残留Terrain。Player、MirrorClone或敌人占用关闭路径时继续使用通用防夹规则。
- 需要阻止Player或MirrorClone从门上方绕过时，门洞剩余部分必须使用标准`Terrain` Tilemap静态墙封闭，优先放在门上方。
- 静态墙始终存在，门只负责自身两个格子的开启、关闭、控制、防夹和重置状态；不得把门洞墙体加入门Prefab或随门一起消失。

## 重置

- 手动重置、死亡重置和重新加载房间时，门与压力板恢复房间定义的初始状态。
- Trigger和压力板的占用列表必须清空，不能保留已销毁对象引用。
- 上述恢复规则只适用于普通门控机关和尚未锁存的双压力板门控组；永久锁存组按存档状态恢复为门开启、两块压力板保持按下。

## 完整踩踏最小回归定义

- Player与MirrorClone分别验证：左侧/右侧半身进入不激活；完整站入后激活；仍与Trigger重叠但身体已越出任一侧边界时释放。
- 完整横向对齐但空中掠过、侧碰、从下方接触均不激活；正常落地后激活。
- 同一角色多个Collider不能绕过主Collider边界；一个角色离开而另一个仍完整踩住时保持激活。
- 回收镜像、镜像死亡、Player死亡重置、重复放置与重新进入场景不保留失效占用；永久锁存组保持存档结果。
- FireballLatch仍仅接受火球；旋转踩踏板按板面方向与角色局部重力验证。
- 既有仅把测试角色中心移入Trigger、未提供落地支撑的PlayMode夹具不再代表有效踩踏，运行前须按新规则调整站位和支撑。

## 下沉永久开关（已确定）

- 新增`DescendingLatch`，使用独立可复用`DescendingLatchSwitch2D.prefab`，普通压力板保持持续占用规则。
- Player、MirrorClone或可推动箱子完整压住时逐渐下压，默认持续踩踏1秒到底；中途全部离开即取消本次进度并回弹，重新踩踏须从头完成。默认回弹0.2秒，参数用于表现调节。
- 只有到底才输出激活信号并开门；之后开关保持按下、门一直开启。死亡、手动重置、镜像回收、切房、退出与读档均保留完成状态，只有新存档清除。
- 每个实例显式配置全局唯一`DoorGroupId`，与双压力板组共用ID命名空间和`latchedDoorGroupIds`存档集合。不得根据名称推断ID；Prefab模板留空，房间实例必须填写。
- 未到底的进度不保存，重置后恢复弹起。用户已确认下沉石台需要实体碰撞与承载：以Kinematic Rigidbody2D和非Trigger顶面Collider承载角色，整体平移下沉，不压缩台身。通过ISurfaceMotionProvider2D提供世界表面速度，复用移动平台承载规则，不挂接或直接移动Player/MirrorClone。始终为安全DynamicSurface，不允许放镜。
- 对应门以该开关为唯一控制源；不得混接临时控制源或双压力板锁存组。

### 下沉开关 Prefab 配置与验证

- 路径：`Assets/Prefabs/Gameplay/Switches/DescendingLatchSwitch2D.prefab`。实例填写`permanentSwitchId`，格式为`区域_房号:DOOR_GROUP:序号`，并检查与其他永久组不重复；门的`controlSource`引用该实例。
- 平顶剪影使用Labnana原始图片`Assets/Art/Generated/FlatTopSwitch.png`，专用材质在渲染时将白底转为透明。实体版按压使用同一剪影整体平移，不改变图形缩放或Collider尺寸。
- 此Prefab为实体下沉石台：默认宽2.5 units，初始顶面在根节点上方0.65 units，实体顶板厚0.46 units，下沉0.6 units，默认1秒下降、1秒回升。Trigger随石台移动并覆盖顶面脚部。根节点在平地上方0.15 units时顶面初始Y=0.8、到底Y=0.2；整个路径必须留足角色净空，不得作为镜子放置表面。
- 最小EditMode回归定义：未到底不开门、离开清零后不能累计短按、到底永久激活、离开仍按下、存档读回和重置保持开门，以及Prefab模式与资源引用。测试位于`PermanentDoorSaveTests.cs`；本次仅静态检查，未运行Unity测试或人工试玩，材质导入与实际踩踏表现待运行验证。

## 可推动箱子占用（2026-09-15已确认）

- 显式PushableCrate2D箱子落稳或推入感应区后按完整宽度、底部位置与向上实体支撑判定；采用箱子主Collider，不根据名称、Tag或质量推断。规则与最小回归见`PUSHABLE_CRATE_SYSTEM.md`。
- Occupancy和DescendingLatch接受箱子，FireballLatch不接受；原角色完整踩踏与永久锁存规则不变。箱子在开关及门之前复位，普通开关重新结算占用，永久结果保留。
