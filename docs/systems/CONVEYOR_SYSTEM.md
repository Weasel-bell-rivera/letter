# 地面传送带系统

## 状态与权威范围

- 当前状态：已确定。
- 用户已确认本文件中的首版规则；本文是地面传送带行为、交互、重置和Prefab配置的权威来源。
- 地面传送带是全局通用地面机关，不属于某个元素区域的专属机制。
- 本系统不替代`docs/systems/MOVING_OBJECTS.md`中的移动平台：移动平台改变自身世界位置，传送带保持固定并向受支撑角色提供表面速度。

## 设计目标

1. 玩家在接触前能够判断移动方向和大致速度。
2. Player与MirrorClone使用完全相同的环境规则。
3. 传送带与角色主动移动可以组合，而不是夺走控制权。
4. 结果不依赖帧率、物理摩擦、对象名称或房间脚本。
5. 失败后可以通过通用重置立即重试，不留下表面速度残留。
6. 允许关卡通过反向输入、传送带和普通实体地形自然分离Player与MirrorClone，不新增冻结、输入锁定或镜像专属传送规则。

## 首版规则摘要（已确定）

| 项目 | 已确定规则 |
|---|---|
| 物理形态 | 固定、水平、安全、可站立的实体地面 |
| 影响对象 | 只影响Player和MirrorClone |
| 默认速度 | `2.5 Unity units/s` |
| 实例速度范围 | `0.5～4.5 Unity units/s` |
| 方向 | 世界坐标左`-X`或右`+X`，实例可配置 |
| 与角色输入组合 | 角色相对传送带的主动速度与传送带表面速度相加 |
| 无输入 | 角色以传送带速度移动 |
| 顺向输入 | 最大世界速度为基础移动速度加传送带速度 |
| 逆向输入 | 基础移动速度减传送带速度；首版速度上限保证角色始终能逆向离开 |
| 跳起或离开 | 保留离开瞬间的世界速度，随后按现有空中控制和减速规则变化 |
| MirrorClone方向 | 传送带是世界环境，不经过镜面输入变换；双方受到同一世界方向表面速度 |
| 镜子放置 | 不允许；运行、暂停或改变视觉均不改变该结果 |
| 伤害 | 不造成伤害 |
| 状态 | 支持初始启用状态和运行时启用/停用；首版不支持运行时反转方向 |
| 重置 | 恢复初始启用状态，并清除所有角色的传送带接触与表面速度状态 |
| 长期存档 | 不保存瞬时状态 |

## 角色运动规则（已确定）

### 支撑判定

- 只有角色落地查询确认传送带Collider是当前支撑面时，传送带才施加表面速度。
- 仅进入视觉区域、Trigger范围、侧面或底部接触均不生效。
- Player使用世界坐标向下作为局部重力方向。
- 首版地面镜生成的MirrorClone同样使用世界坐标向下作为重力方向。
- 角色同时接触多个传送带表面属于非法关卡配置；传送带有效表面不得重叠。
- 相邻同方向传送带应优先合并为一个较长实例，避免接缝重复结算。

### 相邻表面接缝

- 传送带与静态地面相邻时，两者可站立顶面必须处于同一高度，允许误差不超过`0.01 units`。
- 支撑查询同时命中多个Collider时，不得直接采用查询返回顺序。
- 上一固定物理步的支撑Collider仍然有效时，优先保持原支撑，避免在接缝处反复切换。
- 原支撑失效后，依次按距离最近、脚底中心位于表面范围内、运动表面优先于静态表面的顺序选择唯一支撑。
- 每个固定物理步只能选择一个实际支撑Collider，并且只能合成一次该表面的速度。

### 速度组合

传送带提供世界空间表面速度：

```text
ConveyorVelocity = Direction * Speed
```

角色在传送带上的目标切向速度为：

```text
TargetWorldTangentVelocity = CharacterRelativeVelocity + ConveyorVelocity
```

- `CharacterRelativeVelocity`继续使用当前Player移动配置中的最大速度、加速度和减速度。
- 传送带不修改`DefaultPlayerMovement.asset`，不覆盖角色基础参数。
- 表面速度不是额外输入，不改变Player或MirrorClone的面向、输入映射和动画意图。
- 传送带启用、停用或角色首次受到支撑时，表面速度在下一次固定物理步生效，不使用与帧率相关的渐变。
- 角色抵住实体墙时由正常碰撞停止，传送带不得穿透、瞬移或造成夹压伤害。
- 首版最大传送带速度低于Player基础最大速度，确保Player和正常重力MirrorClone可以持续逆向输入离开。

### 离开与跳跃

- 角色跳起、走出边缘或失去支撑时，立即退出传送带接触状态。
- 离开瞬间不删减当前世界速度，避免跳跃时产生突兀横向停顿。
- 离开后的水平速度继续由现有空中控制、加速度、减速度和最大速度规则处理。
- 土狼时间和跳跃输入缓冲仍由角色控制器独立判断；传送带不得单独修改这些计时。
- Player是否成功跳起不影响MirrorClone的传送带状态，反之亦然。

## Player与MirrorClone交互（已确定）

- Player和MirrorClone具有完全相同的进入、离开、速度叠加、碰撞和重置规则。
- 传送带方向属于世界环境状态，不随MirrorClone的反向输入映射而反射。
- 地面镜生成的正常重力MirrorClone可以被水平传送带移动。
- MirrorClone死亡、镜子回收或镜像被立即清除时，必须在同一生命周期流程中移除其传送带接触记录。
- 传送带不得因为对象位于`MirrorClone` Layer而使用不同速度、加速度或资格。

### 单独运输MirrorClone（已确定）

- “单独运输”不是传送带识别MirrorClone后提供特殊效果，而是Player已经离开传送带、只有MirrorClone仍由传送带支撑时的自然物理结果。
- 地面镜生成后，Player与MirrorClone的主动水平输入方向相反；关卡可以让一方走向静态地形，另一方走上顺向传送带，从重叠状态稳定分流。
- 典型用法是Player朝关闭的实体门持续输入并被正常碰撞阻挡，同时MirrorClone沿反向输入与同向传送带被运往远端目标。
- Player被门或墙挡住时仍持续接收并处理输入；系统不得进入`Frozen`、`InputLocked`、自动吸附或其他新增控制状态。
- MirrorClone抵达传送带末端的卡位墙后，由普通实体碰撞停止；传送带不得把它穿过墙壁或吸附到目标位置。
- 传送带也必须以同样规则运输Player。只要Player站上传送带，就不得因关卡预期由MirrorClone使用而忽略Player。

## 关卡谜题语言

### 分流

- 镜子必须放在传送带相邻的静态、安全、水平放置区，而不是直接放在传送带上。
- 放置后通过反向输入让Player和MirrorClone朝相反方向离开重叠位置；传送带只增强其中仍站在带上的角色的世界位移。
- 关键分流结果必须在同一屏或通过稳定镜头构图清楚展示，不能把MirrorClone送出玩家无法观察的区域后要求盲操作。

### 地形卡位

- 卡位只允许使用正常实体碰撞，例如关闭的门、足够高的墙或传送带末端挡墙。
- 卡位地形不得禁用输入、修改移动参数、吸附角色、修正位置或使用房间专用脚本保持角色静止。
- 一方被地形阻挡后，另一方继续按自身输入映射、支撑面和碰撞结果移动；这是现有“输入共享、物理独立”规则的关卡表达。
- 卡位点必须留出反向离开的空间，不能形成只能通过死亡或重新加载解除的夹困。

### 设计禁区

- 不得要求传送带速度与角色主动速度精确抵消来维持静止；加速度、接触切换和浮点误差会让这种解法不可预测。
- 不得按Player或MirrorClone身份配置不同传送带速度、摩擦、碰撞或触发资格。
- 不得用不可见墙、输入冻结、强制位移或房间专用状态伪造“单独运输”。
- 不得把传送带末端直接接到无预警死亡区；教学房必须提供安全卡位墙或可见的无惩罚重试路径。
- 单个谜题只引入一个主要变化。首次教学先展示直线分流，再加入矮墙、间断带面或共享跳跃等地形组合。

## 镜子交互（已确定）

- 地面传送带使用新的显式`Conveyor`表面语义。
- `Conveyor`是物理静态、安全、可站立的表面，但不是合法镜子放置表面。
- 镜子放置系统必须通过表面语义拒绝传送带，不能根据贴图、动画、Prefab名或GameObject名判断。
- 传送带暂停时仍然返回`Conveyor`，因此仍不能放置镜子。
- 放置失败沿用通用约`0.15`秒红色无效轮廓和轻微失败音效，不生成镜子或MirrorClone，也不改变传送带状态。

选择“不允许放置”的理由：镜子目前只批准在静态、稳定且没有运行时表面运动的普通地面或`FrozenGround`上放置。禁止传送带放置可以避免新增“镜子是否随带移动、镜面轴是否移动、镜像生成后如何联动”等第二套核心生命周期规则。

## 启用、停用与控制（已确定）

- 每个实例配置`InitiallyActive`。
- 激活时，视觉运动和表面速度同时启用。
- 停用时，视觉进入明确静止状态，表面速度为零，但实体碰撞保持不变。
- 首版可通过通用激活接口接收压力板、Trigger或其他已批准控制源，不直接依赖具体房间或具体压力板脚本。
- 首版方向是实例固定配置；运行时反转、速度渐变、加速带和周期换向必须作为后续扩展单独批准。
- 控制源状态在固定物理步边界提交，避免视觉方向与实际速度相差一帧。

## 碰撞与安全（已确定）

- 传送带根对象具有与可见地面边界一致的非Trigger实体Collider。
- 传送带实体Collider不使用圆角，`Edge Radius`固定为`0`。
- 传送带与静态地面的连接处不得暴露竖直碰撞边。
- 允许传送带Collider在相邻静态实体内部产生`0.02～0.05 units`的隐藏水平衔接量；该衔接不得形成两个可见或可站立高度不同的表面。
- 视觉平铺宽度、有效传送表面和Collider主体长度必须保持一致；隐藏衔接量不计入谜题有效长度。
- 传送带本身不属于Hazard，不直接杀死Player或MirrorClone。
- 传送带不得把角色送入无逃脱空间、门关闭路径或与Collider不一致的装饰内部。
- 房间布局必须在传送方向末端提供安全站立区、可逆向离开空间或明确的无惩罚重置路径。
- 低顶、墙角和相邻动态对象必须验证不会造成卡死、穿透、抖动或重复接触。
- Player与MirrorClone互相无实体碰撞的现有规则保持不变；二者同时站在同一传送带上时分别独立计算表面速度。

## 重置、死亡与场景切换（已确定）

| 事件 | 传送带结果 |
|---|---|
| 手动重置 | 恢复初始启用状态，清空接触者与临时表面速度 |
| Player死亡 | 先清除MirrorClone与双方表面状态，再恢复传送带初始状态和Player复活点 |
| MirrorClone死亡 | 只清除该MirrorClone接触状态；不重置传送带或Player |
| 镜子回收 | 立即清除MirrorClone接触状态；不重置传送带 |
| 场景切换 | 不保留接触、表面速度或临时启用状态；目标房间加载实例初始状态 |
| 重新进入房间 | 加载实例初始状态 |
| 读取存档 | 不读取传送带瞬时状态 |

- 传送带实现统一`IRoomResettable`或等价房间状态协议。
- 重置期间必须先冻结角色物理响应，再清除传送带接触，避免恢复过程中产生一次额外位移。
- 传送带不创建长期存档字段。

## 视觉与反馈（已确定）

- 玩家在踏上传送带前必须能看出方向；表面使用连续箭头、履带纹理或明确运动图案。
- 动画移动方向必须与实际世界表面速度一致。
- 不同速度至少通过动画频率体现；若未来只保留一个速度档位，则所有实例使用同一动画频率。
- 停用状态必须与激活状态清晰区分，且不能只靠声音。
- 边界、可站立表面和实体Collider必须一致。
- 传送带可使用低音量循环机械声，进入、离开不需要文字提示。
- 区域Prefab Variant可以更换视觉和声音，但不能改变速度组合、对象资格、镜子交互或重置规则。

## 技术架构

Prefab路径：

```text
Assets/Prefabs/Gameplay/Surfaces/GroundConveyor2D.prefab
```

Prefab结构：

```text
GroundConveyor2D
├─ Visual
│  ├─ BeltRenderer
│  └─ DirectionIndicator
└─ SurfaceProbeDebug（仅编辑器或开发构建）
```

根对象包含：

- Static `Rigidbody2D`或等价静态Collider结构。
- 非Trigger `BoxCollider2D`。
- 返回`Conveyor`的`SurfaceSemantic2D`。
- 提供方向、速度、启用状态和重置的`GroundConveyor2D`。
- 通用激活接收接口。

角色侧通过统一表面运动接口读取：

```text
ISurfaceMotionProvider2D
└─ TryGetSurfaceVelocity(worldContactPoint, supportNormal, out velocity)
```

- Player与MirrorClone的移动控制器读取同一接口，不由传送带脚本直接查找并写入具体角色Rigidbody。
- 表面速度在角色固定物理步内与主动移动合成，避免依赖物理材质摩擦。
- 接触资格来自角色已有落地查询与统一表面语义，不使用Trigger占用作为唯一依据。
- 传送带长度、Collider尺寸和Tiled Sprite宽度必须通过Prefab实例配置保持同步。

## Prefab实例允许配置

- 位置。
- 长度和对应视觉平铺宽度。
- 左/右方向。
- `0.5～4.5 units/s`范围内的速度。
- 初始启用状态。
- 不改变玩法边界的视觉和声音配置。

## Prefab实例禁止配置

- Player与MirrorClone不同的速度或资格。
- 镜子放置资格。
- Player或MirrorClone基础移动参数。
- 伤害、死亡或夹压规则。
- 房间专用输入、碰撞Layer或重置流程。
- 运行时方向反转、非水平表面或重叠传送带；这些需要后续规则批准。

## 测试与验收

### EditMode/资产测试

- Prefab存在且必需组件、引用和表面语义完整。
- Collider、Tiled Sprite和方向指示边界一致。
- 速度范围、方向和初始状态配置合法。
- Prefab不包含房间编号、世界坐标或房间专用脚本。
- `Conveyor`不被镜子放置查询视为合法表面。

### PlayMode测试

- 无输入Player和正常重力MirrorClone以完全相同的传送带速度移动。
- 顺向和逆向输入结果符合速度叠加公式。
- Player和MirrorClone同时站立时独立移动，不互相碰撞或重复叠加。
- Player离开带面而MirrorClone继续受支撑时，只有MirrorClone继续获得表面速度；反向情况结果相同。
- Player与MirrorClone从静态地面反复进入、离开传送带时，不得卡边、抖动或在两个支撑Collider之间连续切换。
- 侧面、底部、Trigger重叠和空中经过不施加表面速度。
- 跳起和走出边缘后接触状态清除，离开瞬间速度连续。
- 启用、停用和视觉状态在同一固定物理步生效。
- 抵住墙壁时不穿透、不受伤，持续逆向输入可以离开。
- 镜子放置失败不改变镜子、MirrorClone或传送带状态。
- MirrorClone死亡和镜子回收立即清理接触记录。
- 手动重置、Player死亡、重新进房和场景切换恢复初始状态且无速度残留。
- 修改贴图、动画、GameObject名或房间编号不会改变交互结果。

### 人工试玩

- 玩家在接触前能稳定判断方向。
- 默认`2.5 units/s`能明显影响路线，但逆向操作不会显得失控。
- 顺向跳跃的距离增量可理解，不产生意外精确跳跃要求。
- Player与MirrorClone同时出现在画面中时，传送带规则无需文字解释仍可推导。
- 玩家能够理解“单独运输”来自当前支撑面差异，而不是MirrorClone拥有特殊传送权限。
- 地形卡位期间输入始终有效，角色反向输入后能够正常离开卡位点。

## 已确认的核心决定

用户已经整体确认以下规则：

1. 表面速度与角色主动速度相加，而不是用力推动或覆盖角色速度。
2. 默认速度`2.5 units/s`，实例允许范围`0.5～4.5 units/s`。
3. 离开或跳起时保留离开瞬间世界速度。
4. 传送带世界方向不会随镜面变换。
5. 首版只影响Player和MirrorClone。
6. 传送带始终禁止放置镜子，包括停用状态。
7. 首版只做水平地面版本，不做墙面、天花板、反转或变速版本。
8. 首版支持启用/停用，但运行时不反转方向。
9. 允许关卡通过反向输入让Player离开带面、MirrorClone继续受传送带支撑，从而单独运输MirrorClone。
10. 地形卡位只使用普通实体碰撞；传送带系统不新增冻结、输入锁定、自动吸附或身份过滤。
