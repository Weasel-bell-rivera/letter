# 重置与场景状态

## 适用范围

本文档定义手动重置、玩家死亡重置、离开房间、重新进入房间和场景切换时的权威状态规则。镜子、镜像与玩家之间的直接联动同时参见 `docs/MIRROR_MECHANIC.md`。

## 重置类型

- 手动重置
- 玩家死亡重置
- 镜像死亡处理
- 镜子被破坏后的处理
- 离开并重新进入房间
- 场景切换
- 读取存档

## 实现约束

### 统一执行顺序（已确定）

手动重置和玩家死亡重置必须使用以下顺序，其他系统文档不得定义不同顺序：

1. 冻结Player输入和角色物理响应，防止重置过程中继续产生交互。
2. 清除MirrorClone并将镜子回收到Player，同时清理Trigger、压力板和事件占用。
3. 暂停门、敌人、移动对象和危险物的运行与伤害判定。
4. 恢复所有房间瞬时对象的初始状态，并重新应用当前存档中的永久锁存门控组状态。
5. 验证当前复活位置安全，并把Player移动到复活位置、清空速度和临时运动状态。
6. 恢复碰撞、物理、危险物运行和Player输入。

- 所有需要恢复的房间对象必须通过统一重置协议或房间状态管理器处理。
- 不得让具体房间通过重新加载整个游戏来掩盖状态清理问题。
- 镜像消失后必须清除其留下的Trigger、压力板和事件订阅状态。
- MirrorClone死亡或消失、镜子回收或被破坏时仍须清理永久锁存压力板的占用引用，但不得解除已经提交的机关组锁存状态。
- 玩家死亡时，镜像立即消失、镜子回到玩家手中，然后执行其余房间状态恢复。
- 镜像单独死亡或镜子单独被破坏时，不触发整个房间的死亡重置。
- MirrorClone被敌人杀死时只执行镜像死亡联动，不重置地面巡逻敌人的位置、方向、巡逻阶段或冻结状态，不重置竖直墙面巡逻敌人的位置、方向或等待计时，也不重置逐风鳐的位置、目标或攻击阶段。
- MirrorClone被投火者或火球杀死时只执行镜像死亡联动；投火者保持当前阶段，已锁定方向的发射不取消，在途火球除命中者外不因镜像死亡而清除。
- 投火者在手动重置、Player死亡重置和场景切换时必须清除其目标、蓄力、冷却以及全部在途火球；旧房间不得留下延迟发射或对象池返回事件。
- Player被敌人杀死时执行完整房间重置；地面巡逻敌人恢复初始活动状态，竖直墙面巡逻敌人恢复初始路径状态，逐风鳐恢复初始守卫状态，Player和MirrorClone清除寒冰运动状态。
- 重置和场景切换必须清除Player与MirrorClone记录的传送带支撑Collider和已施加表面速度；传送带恢复实例初始启用状态。
- 静态`FrozenGround` Tilemap不在重置时生成、删除或修改Tile。
- 静态`FreezingGroundCell2D` Prefab实例不在重置时生成、删除或修改。
- Player因`FreezingGround`完全冻结时按Player死亡执行完整统一重置。
- MirrorClone因`FreezingGround`完全冻结时只执行镜像死亡与镜子回收，不重置房间或Enemy冻结进度。
- 重置Player、MirrorClone或Enemy时必须清除冻结量、首次接触目标格、表面接触引用和临时移动倍率。
- 手动重置与玩家死亡重置使用同一套房间瞬时状态恢复规则。
- 场景切换时不得携带已放置的镜子、镜像、Trigger占用或临时机关状态。
- 永久拾取物和永久区域进度必须由持久化状态管理，不能依赖Scene对象是否仍然存在。
- 永久锁存双压力板门控组属于存档级永久进度，不得被手动重置、死亡重置、场景切换或重新进入房间清除；只有开始新存档才清除。
- 永久拾取物和永久区域进度跨游戏关闭与重新启动保留，并在状态改变时立即请求写入存档。
- 存档写入失败时必须保留内存状态、记录错误并允许安全重试，不得静默丢失永久进度。
- 复活点规则见 `docs/systems/CHECKPOINT_SYSTEM.md`。
- 运行时生成敌人的出生点与Spawner恢复顺序见`docs/systems/ENEMY_SPAWN_SYSTEM.md`；出生点本身没有可重置的玩法状态，统一重置只清理生成请求和临时占用，并通知Spawner恢复其批准的初始状态。
