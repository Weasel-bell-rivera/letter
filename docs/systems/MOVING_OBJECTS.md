# 移动对象系统

## 状态与权威范围

- 当前状态：已确定。
- 本文定义移动门、移动平台和周期移动障碍的职责边界。
- 地面传送带自身不移动，不属于本文的移动平台；其规则见`docs/systems/CONVEYOR_SYSTEM.md`。
- 首版通用移动平台采用两个端点之间的确定性往返运动；多节点路径、旋转平台和运行时缩放不属于首版移动平台规则。
- 移动门继续以`docs/systems/DOOR_SYSTEM.md`为权威来源，不能用移动平台Prefab替代。

## 类型划分

### 移动门

- 用于阻挡或开放通道。
- 通常由压力板或Trigger控制，不作为可站立运输平台设计。
- 使用 `docs/systems/DOOR_SYSTEM.md` 的防夹和重置规则。

### 移动平台

- Player和MirrorClone可以站在平台上并随平台稳定移动；平台运动作为支撑面的世界空间速度与角色自身相对运动组合。
- 平台不得通过Transform瞬移造成角色穿透。
- 平台路径、速度、等待时间和初始相位必须可以配置。
- 首版路径由平台实例位置作为路径锚点、两个本地坐标端点组成；Prefab资产不得包含正式房间世界坐标。
- 平台以固定速度在两端点之间移动，到达端点后等待配置时长，再沿原路径反向移动。
- 初始相位使用`0～1`归一化路径位置，初始方向和初始运行状态分别配置；相同配置必须产生相同运动结果。
- 首版移动平台只改变位置，不在运行时旋转或缩放。
- Player和MirrorClone离开支撑面或主动跳起后不再读取平台后续速度，不建立父子Transform关系；离开瞬间已经具有的世界速度继续由角色自身运动规则处理。
- 特殊墙面镜生成的MirrorClone按自身局部重力方向判断是否受到平台支撑；不得把世界坐标上方写死为唯一可站立方向。
- 平台是安全动态实体，本身不造成伤害。房间路径必须预留完整角色空间，不得把角色夹在平台和静态地形之间作为谜题或惩罚。
- 移动平台返回`DynamicSurface`表面语义，不是静态地形、普通固定平台或`FrozenGround`。
- 镜子不能放置在移动平台上；平台区域外观不得改变该结果。

## 通用移动平台Prefab

资产路径：`Assets/Prefabs/Gameplay/Platforms/MovingPlatform2D.prefab`

```text
MovingPlatform2D
└─ Visual
```

默认视觉使用`Assets/Art/Kenney/NewPlatformerPack/Sprites/Tiles/Default/terrain_stone_cloud_middle.png`，按`64 PPU`、Point Filter和Full Rect导入，并由`SpriteRenderer`横向平铺。默认Collider对齐该图片的不透明像素边界；修改实例尺寸时必须同步保持视觉边界和Collider一致。

根对象必须包含：

- `Rigidbody2D`，Body Type为Kinematic，使用连续碰撞检测和插值。
- 与可见平台边界一致的非Trigger `BoxCollider2D`。
- 返回安全、非静态`DynamicSurface`的`SurfaceSemantic2D`。
- 管理路径、运动、乘客承载和重置的`MovingPlatform2D`通用组件。

房间实例允许覆盖：

- Transform位置与初始旋转；Transform位置是路径锚点。
- 平台尺寸，但视觉边界和Collider必须保持一致。
- 两个本地坐标端点。
- 移动速度、端点等待时间、初始相位、初始方向和初始运行状态。
- 不改变碰撞轮廓与玩法规则的区域视觉。

房间实例不得覆盖：

- Player与MirrorClone的承载资格或为二者设置不同速度。
- `DynamicSurface`语义和镜子禁止放置规则。
- 重置、死亡和场景切换规则。
- 把平台改成Hazard、移动门或周期移动障碍。

配置非法时必须报告错误并停止运动，包括端点重合、速度非正数、等待时间为负数或初始相位超出范围。编辑器选中平台时必须显示端点与路径辅助线，让设计者在运行前判断路径。

### 周期移动障碍

- 持续按照固定、可观察的路径或周期移动。
- 是否造成伤害由Hazard配置决定，不得仅凭对象名称推断。

## 实现约束

- 三种对象使用不同职责的组件或Prefab，不使用单个脚本隐式切换全部行为。
- MirrorClone与可推动动态物体的交互能力等同于Player：使用相同的实体碰撞、质量、推力、推动条件和被推动规则。动态物体不得仅因碰撞者是MirrorClone而采用不同参数或结果。
- 房间重置后恢复初始位置、方向、计时和激活状态。
- 路径和周期不得根据玩家位置随机变化，除非该行为以后作为独立机制批准。
- 移动平台通过Kinematic `Rigidbody2D.MovePosition`在固定物理步中移动；不得逐帧直接写Transform位置。
- 每个运动物理步必须先由平台根据计划位移计算并发布世界空间表面速度：`(目标位置 - 当前Rigidbody位置) / fixedDeltaTime`；等待、停用和重置状态发布零速度。
- `MovingPlatform2D`的固定步计算必须先于Player和MirrorClone控制器。角色只从当前局部重力方向上的实际支撑Collider读取当步表面速度。
- 角色在自己的固定步中先扣除上一物理步已经合成的同一支撑面速度，再计算输入、重力和跳跃形成的相对速度，最后只合成一次当前平台速度；不得逐帧累加。
- 平台不得直接写入乘客的`Transform.position`或`Rigidbody2D.position`，也不得同时使用位置搬运与表面速度两套承载路径；角色与平台各自保持Rigidbody插值连续。
- 承载不得修改角色自身输入速度、重力或跳跃参数。角色离开边缘或起跳后不再接收平台后续速度，但保留离开瞬间的世界速度。
- 平台运行状态属于房间瞬时状态，不写入长期存档。手动重置和Player死亡时先恢复平台，再把Player放到复活点；场景切换加载目标房间平台初始状态。

## 验收要求

- 平台能从任意合法初始相位确定性地往返，并严格执行端点等待。
- Player和MirrorClone在水平、垂直或斜向路径上保持稳定承载；主动移动和跳离不受阻止。
- 平台和角色同时启用Rigidbody插值时，渲染帧中的角色相对平台位置必须连续，不得因直接改写乘客位置产生周期性抖动。
- MirrorClone使用旋转后的局部重力时，支撑方向仍正确。
- 手动重置、Player死亡和重新进入房间后，位置、方向、等待计时和运行状态全部恢复。
- 镜子放置查询拒绝移动平台，失败不改变镜子、镜像或机关状态。
- 平台不产生伤害，不把角色夹入静态地形；路径配置在编辑器中可观察。
- Prefab引用完整，房间实例保持Prefab连接，不包含房间编号或正式房间世界坐标。
