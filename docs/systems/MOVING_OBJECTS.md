# 移动对象系统

## 类型划分

### 移动门

- 用于阻挡或开放通道。
- 通常由压力板或Trigger控制，不作为可站立运输平台设计。
- 使用 `docs/systems/DOOR_SYSTEM.md` 的防夹和重置规则。

### 移动平台

- Player和MirrorClone可以站在平台上并随平台稳定移动。
- 平台不得通过Transform瞬移造成角色穿透。
- 平台路径、速度、等待时间和初始相位必须可以配置。

### 周期移动障碍

- 持续按照固定、可观察的路径或周期移动。
- 是否造成伤害由Hazard配置决定，不得仅凭对象名称推断。

## 实现约束

- 三种对象使用不同职责的组件或Prefab，不使用单个脚本隐式切换全部行为。
- MirrorClone与可推动动态物体的交互能力等同于Player：使用相同的实体碰撞、质量、推力、推动条件和被推动规则。动态物体不得仅因碰撞者是MirrorClone而采用不同参数或结果。
- 房间重置后恢复初始位置、方向、计时和激活状态。
- 路径和周期不得根据玩家位置随机变化，除非该行为以后作为独立机制批准。
