# 收藏品与道具拾取系统

## 文档职责

本文定义拾取物分类、唯一标识、拾取资格、生命周期、存档关系和验收标准。持久化细节见 `docs/systems/SAVE_SYSTEM.md`，重置顺序见 `docs/systems/RESET_SYSTEM.md`。

## 设计目标

- 临时效果与永久进度严格分离。
- 永久收藏不会因死亡、重置、切换房间或退出游戏丢失。
- 永久对象稳定去重，不能反复进房重复领取。
- Player在接触前能分辨道具类别，拾取后有明确反馈。

## 拾取物分类

| 类型 | 用途 | 死亡/手动重置 | 重进房间/重启 | 计入收藏统计 |
|---|---|---|---|---|
| `TemporaryPickup` | 本次房间尝试的机制道具 | 恢复 | 不保留 | 否 |
| `PermanentAbility` | 永久能力，例如镜子 | 保留 | 保留 | 否 |
| `PermanentCollectible` | 可选探索收藏 | 保留 | 保留且不再生成 | 是 |
| `ProgressionItem` | 已批准的区域或世界解锁物 | 保留 | 保留且不再生成 | 默认否 |

类型必须显式配置，不得根据Prefab名称推断。

## 通用规则（已批准）

- 只有Player可以完成拾取；MirrorClone进入Trigger也不能改变道具或进度。
- 暂停、死亡、重置和场景切换期间不接受拾取。
- 同一对象的同帧重复碰撞只能结算一次。
- 临时拾取物及效果在死亡或手动重置后恢复，不写入长期存档。
- 永久拾取成功后立即更新内存状态并请求存档。
- 永久拾取不因死亡、手动重置或场景切换恢复。
- 写入失败时保留内存状态并安全重试，不回滚奖励、不重新生成对象。

## 永久对象ID

格式为 `<ROOM_ID>:<TYPE>:<NN>`，例如：

```text
CENTER_001:ABILITY:01
FIRE_004:COLLECTIBLE:01
```

- `TYPE` 仅使用 `ABILITY`、`COLLECTIBLE`、`PROGRESSION`。
- `NN` 是房间内从 `01` 开始的两位序号。
- ID必须全局唯一；房间编号必须与地图、房间文档和Scene一致。
- 已进入玩家存档的ID不得复用；改名必须提供存档迁移映射。
- 临时拾取可有重置用的场景内ID，但不得写入永久集合。
- `collectedPermanentIds` 统一记录`PermanentAbility`、`PermanentCollectible`和`ProgressionItem`的拾取ID，作为永久拾取防重复的权威集合。
- 永久能力除记录拾取ID外，还必须把稳定能力ID写入`unlockedAbilities`；镜子的稳定能力ID为`MIRROR`。

## 拾取事务

永久拾取按固定顺序处理：

1. 验证触发者、系统状态和对象状态。
2. 查询内存中的永久ID集合，已有记录则拒绝重复结算。
3. 将ID加入内存状态并应用能力、收藏或进度奖励。
4. 立即禁用Trigger和表现，防止重复触发。
5. 播放一次获得反馈。
6. 请求存档；失败则进入重试队列，但不回滚本次领取。

临时拾取只把效果登记到当前 `RoomAttemptState`，由统一重置流程清除。

## 加载与显示

- 存档读取完成前，永久拾取物不得开放显示和交互。
- 已领取的永久对象不启用Sprite、Collider、Trigger或获得提示。
- 未领取对象按房间文档的初始位置生成。
- 永久能力、永久收藏和临时机制道具使用不同的视觉语言。
- 拾取成功至少提供清晰视觉反馈；永久收藏反馈应显示项目及区域收集数，UI样式后定。
- 首版存档数据提供房间、区域和全世界三级收藏统计所需的查询接口；正式统计UI延后制作。

## 房间文档要求

包含拾取物的房间文档必须记录：ID、类型、位置与到达路径、必经或可选、效果、重置结果、持久化结果、是否参与区域解锁，以及防重复与软锁检查。通用拾取和存档逻辑不得写入房间专用脚本。

## 已批准实例

### CENTER_001 镜子

- ID：`CENTER_001:ABILITY:01`
- 类型：`PermanentAbility`
- 新游戏拾取后永久解锁镜子并立即请求存档。
- 已解锁存档不再生成该对象，也不重复首次获得流程。
- 该拾取同时登记永久拾取ID`CENTER_001:ABILITY:01`和能力ID`MIRROR`。

### 风区失重之羽

- 类型：`TemporaryPickup`，当前实现名 `GravityDisablePickup2D`。
- 仅属于风区，只影响本次房间尝试的MirrorClone，不计入收藏。
- 镜像死亡时效果保留；玩家死亡、手动重置或切换场景时清除并按规则恢复道具。
- 完整规则见 `docs/regions/WIND_REGION.md`。

## 验收标准

- Player能按规则拾取各类型对象，MirrorClone不能拾取。
- 临时物在死亡和手动重置后恢复，且不跨房间。
- 永久物在死亡、重置、切换房间和重启后保持领取。
- 相同永久ID不会重复发奖，重复配置能被编辑器检查或测试发现。
- 拾取后立即结束进程，重启后状态仍正确。
- 模拟写入失败时不回滚、不重复奖励，恢复后能成功重试。
- ID迁移后，领取状态和统计保持正确。

## 首版范围（已确认）

- 首版实现通用拾取、去重、持久化和三级统计查询基础设施，但不制作具体可选收藏品。
- 可选收藏品的正式名称、叙事意义、视觉形态和单房间数量上限留到具体收藏内容设计时批准；在批准前不得配置正式实例。
- 首版收藏品只提供完成度数据，不自行解锁奖励、隐藏房或结局。此类用途必须由后续已批准的进度规则显式声明。
- 首版不配置实际`ProgressionItem`。系统只保留类型明确的扩展接口，不得在世界流程规则批准前自行解锁区域。
