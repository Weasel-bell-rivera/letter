# 逐风鳐敌人设计

## 状态与权威范围

- 正式玩法名称：逐风鳐。
- 当前实现名称：`WindRayEnemy2D`。
- 区域归属：风之区域。
- 当前状态：核心行为与首版统一原型数值已确认；正式美术待后续制作。
- 本文是逐风鳐的感知、选取目标、攻击、碰撞、镜像交互、重置和房间配置规则的权威来源。
- 通用敌人伤害与生命周期规则同时参见`docs/systems/ENEMY_SYSTEM.md`，风区定位参见`docs/regions/WIND_REGION.md`。
- 本设计不依赖风区道具或其他临时区域效果；没有获得任何区域道具时也必须完整成立。

本文同时定义死亡规则不同的独立原型`SacrificialWindRayEnemy2D`（正式玩法名称：殉风鳐）。殉风鳐共享本文的感知、目标选择、锁定、冲刺和统一数值，但按下文“殉风鳐变种”处理命中与死亡。

逐风鳐首个灰盒教学房为`WIND_001`。正式房间必须复用统一配置，不得逐实例修改感知与攻击数值。

## 设计目标

逐风鳐是一种以镜像诱敌为主要解法的空中敌人。它守在Player必须经过的位置附近，并攻击进入一定距离的Player或MirrorClone。玩家通过让MirrorClone成为更近的目标，将逐风鳐引离Player的路线，再利用敌人的喘息和返回阶段通过。

核心洞察是：

> 逐风鳐攻击离自己更近的角色；MirrorClone可以主动抢走目标，把敌人引到别处。

逐风鳐不承担自由追踪、随机游荡、弹幕、风力推动或重力改变功能。它的风区身份来自悬浮姿态、冲刺运动和气流表现，而不是另一套未定义的角色物理规则。

## 状态模型

```text
Guarding
   |
   | 有资格的目标进入感知范围且无遮挡
   v
Windup
   |
   | 预警结束
   v
Dashing
   |
   | 到达锁定点、达到最大行程或被实体阻挡
   v
Recovering
   |
   | 喘息结束
   v
Returning
   |
   | 回到守卫点
   +----------------------------> Guarding
```

### `Guarding`

- 逻辑位置固定在房间实例配置的守卫点。
- 允许视觉子对象进行不改变Collider和感知中心的轻微悬浮动画。
- 按固定频率检测Player和MirrorClone，不使用随机数。
- 只有在此状态下可以获取新目标。
- 身体伤害保持启用。

### `Windup`

- 进入状态时立即确定目标，并记录目标当时的世界坐标作为本次攻击的锁定点。
- 预警期间不重新选择目标，也不随着目标继续移动而改变锁定点。
- 必须通过目标标记、冲刺方向线、收拢双翼和声音明确表现本次攻击对象与路线。
- 目标在预警期间离开感知范围、移动到掩体后或因镜像回收而消失，均不取消已经锁定的攻击。
- 身体伤害保持启用。

### `Dashing`

- 从当前位置沿朝向锁定点的直线冲刺。
- 冲刺开始后不转向、不追踪、不重新选取目标。
- 到达锁定点、达到统一最大冲刺行程或被实体Collider阻挡时立即结束冲刺。
- 冲刺伤害由与逐风鳐可见身体轮廓一致的伤害Trigger产生，不沿整条路线预先生成伤害。
- 冲刺不得穿过静态地形、关闭的门或其他实体阻挡物。

### `Recovering`

- 停留在冲刺结束位置并停止主动攻击。
- 不获取新目标，也不再次冲刺。
- 身体接触伤害仍然存在；逐风鳐不会变成安全平台。
- 疲软轮廓和声音必须清晰显示剩余安全通过窗口。

### `Returning`

- 沿直线以低于冲刺速度的统一速度返回守卫点。
- 返回期间不获取新目标。
- 身体接触伤害仍然存在。
- 被关闭的门或其他实体阻挡时停止返回，阻挡解除后继续；不得穿透或向阻挡物持续施加推力。
- 到达守卫点后清空目标、锁定点和临时计时，重新进入`Guarding`。

## 感知与目标选择

### 感知范围

- 感知范围是以逐风鳐逻辑中心为圆心的固定世界距离，不使用预设风道或只能朝前感知的矩形区域。
- 感知距离、边缘提示距离和检测频率由风区统一配置，不允许具体房间单独改变。
- 房间实例只配置守卫点和初始视觉朝向，不通过缩放Transform改变感知距离。
- 不显示感知半径圆环、风环边界或其他精确量尺。角色进入感知边缘提示距离时，只让逐风鳐本体出现轻微冷色警觉变化；正式锁定后再显示预警染色和目标标记。
- Editor Gizmo只用于制作检查，不能替代游戏内可见反馈。

### 遮挡

- 目标与逐风鳐感知中心之间必须无遮挡。
- 静态实体地形和完全关闭的门阻挡感知。
- 镜子为非实体装置，不阻挡感知，也不会成为目标。
- 不得通过Tile名称、Sprite名称、GameObject名称、具体Tilemap名称或房间编号判断遮挡。

### 目标资格与优先级

- Player和当前存在的MirrorClone具有完全相同的目标资格。
- 逐风鳐不以镜子、压力板、移动平台、门、其他敌人或装饰为目标。
- 只有处于感知距离内且无遮挡的角色参与选择。
- 进入`Windup`时选择距离逐风鳐最近的合格角色。
- 已经进入`Windup`后不得因另一个角色变得更近而切换目标。
- 如果Player与MirrorClone在同一个固定物理步中距离完全相同，使用Player作为确定性的平局目标；目标标记必须立即显示结果，房间不得把精确平局作为预期解法。

## 攻击与角色交互

以下默认规则适用于基础`WindRayEnemy2D`。殉风鳐的覆盖规则见本节末尾。

### 命中Player

- Player立即进入统一死亡重置流程。
- MirrorClone立即消失并清理Trigger、压力板和事件占用。
- 已解锁的镜子回到Player手中。
- 逐风鳐随房间瞬时状态一起恢复到初始守卫状态。

### 命中MirrorClone

- MirrorClone立即死亡并清理全部交互占用。
- 镜子自动回到Player手中。
- Player不死亡，房间不执行整体重置。
- 逐风鳐不因MirrorClone死亡而重置或返回守卫点；它继续完成当前冲刺，然后进入`Recovering`。

### 躲避与主动回收

- 因为锁定点在`Windup`开始时已经记录，目标可以在冲刺前离开该点来躲避攻击。
- Player可以让MirrorClone触发锁定后主动回收镜子；逐风鳐仍然攻击已记录的锁定点。
- 镜子回收的固定帧处理优先级仍以`docs/MIRROR_MECHANIC.md`为准，逐风鳐不得阻止或延迟回收。
- 成功诱敌不要求牺牲MirrorClone；保住MirrorClone可以支持后续压力板或路径谜题。

### 殉风鳐变种（已确定）

- 殉风鳐命中MirrorClone时，先执行镜像死亡与镜子回收，再进入`Defeated`状态。
- `Defeated`期间停止感知、移动、伤害、目标标记和冲刺拖尾，并隐藏本体；Player与房间不整体重置。
- 殉风鳐命中Player时仍由Player触发完整房间重置；殉风鳐随同一次统一重置恢复，因此不会在重置后的新尝试中保持死亡。
- 手动重置、Player死亡重置或重新进入房间时，殉风鳐恢复守卫点、`Guarding`和全部初始反馈。
- MirrorClone被其他危险杀死或被主动回收不会击败殉风鳐；只有殉风鳐自身伤害Trigger成功命中角色才触发击败结果。
- 此差异改变敌人死亡和重置规则，因此殉风鳐使用独立基础Prefab，而不是Unity Prefab Variant。

## 碰撞与其他对象

- 逐风鳐是动态玩法对象，不属于Tilemap。
- 首版身体与伤害轮廓约为`1.15 × 0.7 units`，属于普通小怪尺寸；游戏中不绘制外围探测圈。
- 身体使用Kenney Double Bee三帧素材，按`rest → a → b → a`、`8 FPS`循环播放；动画只改变Sprite，不改变碰撞、感知或攻击计时。
- 逐风鳐不受Player或MirrorClone推动，不把角色持续挤向墙壁，也不夹住角色。
- Player和MirrorClone不能站在逐风鳐上。
- 逐风鳐不能触发压力板，不能推动门或移动平台，也不破坏镜子。
- 逐风鳐及其任何状态都不是镜子放置表面。
- 逐风鳐首版不可冻结、不可击杀、不可眩晕，也不受普通环境风力影响。
- 关闭的门会阻挡感知和冲刺。门关闭路径被逐风鳐占用时必须暂停关闭，不能夹死、推出或穿过敌人。
- 首版不允许多只逐风鳐在同一活动空间内互相阻挡；需要多敌人组合时，其感知范围、冲刺范围和返回路径必须空间分离。

## 房间使用规则

- 首次出现前必须提供位于感知范围外的安全观察位置。
- Player进入房间时不得已经处于无遮挡的感知范围内。
- 房间必须同时提供一个MirrorClone可到达的诱敌点和一条Player可利用的通过路线。
- 诱敌点必须让MirrorClone可以明显比Player更接近逐风鳐，不能依赖像素级距离比较。
- 喘息与返回时间必须为标准移动参数下的Player留下稳定通过窗口，不要求极限跳跃或帧级操作。
- 墙壁、门和前景美术不得遮住目标标记、范围提示或冲刺路线。
- 不得通过房间专用脚本修改目标资格、平局规则、锁定时机或重置行为。
- 房间需要不同难度时，优先改变地形、诱敌点和通过路线，不改变逐风鳐的核心感知与攻击数值。

## 表现要求

- 轮廓结合鳐鱼、风筝和鸟翼，宽而扁，确保与地面巡逻敌人清晰区分。
- `Guarding`：双翼展开，环绕气流稳定。
- `Windup`：双翼收拢，气流向身体聚集，目标与锁定点出现明确标记。
- `Dashing`：产生与实际运动方向一致的短拖尾，不用拖尾代替真实伤害边界。
- `Recovering`：双翼下垂、气流中断，显示暂时不会再次锁定。
- `Returning`：使用缓慢而稳定的逆风动作，与冲刺速度形成明显区别。
- 所有状态切换同时提供视觉和声音反馈，不能只靠颜色表达。

## 首版统一数值

| 参数 | 首版值 |
|---|---:|
| 感知半径 | `6 units` |
| 感知边缘提示距离 | `0.75 units` |
| 预警时间 | `0.75 s` |
| 冲刺速度 | `12 units/s` |
| 最大冲刺行程 | `7 units` |
| 喘息时间 | `1.5 s` |
| 返回速度 | `2 units/s` |
| 到达锁定点与守卫点的距离容差 | `0.05 units` |

这些数值保存到`Assets/Settings/Enemies/DefaultWindRayEnemy.asset`，所有逐风鳐实例共同使用。正式房间不得逐实例覆盖。

## 重置、场景切换与存档

手动重置、Player死亡重置或重新进入房间时：

- 回到房间配置的初始守卫点和初始视觉朝向。
- 清空线速度、角速度、目标引用、锁定点和遮挡查询结果。
- 清空预警、冲刺、喘息和返回计时。
- 恢复`Guarding`状态、身体伤害和初始视觉。

MirrorClone单独死亡或镜子主动回收不重置逐风鳐。场景切换不携带逐风鳐的位置、状态、目标或计时。全部状态属于`RoomAttemptState`，不写入长期存档。

## 验收标准

- Player和MirrorClone在同一距离与遮挡条件下具有相同目标资格。
- 最近目标规则、平局规则和锁定结果确定且不依赖帧率或对象查询顺序。
- 墙壁和关闭的门稳定阻挡感知与冲刺。
- 锁定后目标移动、镜像回收或目标被遮挡不会改变已记录的锁定点。
- 冲刺只沿一条直线执行，不追踪、不转向且不穿过实体Collider。
- 命中Player触发完整房间重置；命中MirrorClone只执行镜像死亡联动。
- MirrorClone单独死亡或主动回收不会重置逐风鳐。
- `Recovering`和`Returning`期间不获取新目标。
- 手动重置、Player死亡和场景切换不会留下位置、目标、速度、计时或视觉残留。
- 逐风鳐不能触发压力板、破坏镜子、成为平台或镜子放置表面。
- 不依赖任何风区道具也能完成安全观察、镜像诱敌和Player通过的完整谜题闭环。
