# 无障碍与多分辨率系统

## 状态与范围

本文定义首批可复用的无障碍偏好、UI响应式布局契约和验证档位。它不改变玩法、相机边界、输入绑定、本地化语言范围、字幕规则或最低硬件规格。

当前运行时暂停设置菜单已经接入三项偏好、响应式Canvas、安全区域、滚动内容和非颜色键盘焦点。场景与其他UI仍需由各自所有者按下文清单接入。`1024×768`是验证档位，不代表已经声明的最低支持分辨率。

## 已确认偏好

| 偏好 | 支持值 | 默认值 |
|---|---|---|
| 文本缩放 | 100%、125%、150% | 100% |
| 高对比 | 开、关 | 关 |
| 减弱动态 | 开、关 | 关 |

- 非法文本缩放值安全回退到100%。
- 偏好写入独立的`accessibility-settings.json`，不进入长期游戏进度存档，也不复制显示、画质或音量设置服务的职责。
- 写入采用临时文件验证、主文件替换和单一有效备份；读取失败时使用安全默认值。
- 无障碍服务只有在文件写入并校验成功后才发布新的`Current`并发送事件；失败时运行时状态保持原值。
- 暂停设置同时提交显示/音频设置与无障碍偏好时保留两套原始快照。无障碍提交失败时不开始显示设置提交；第二阶段显示设置失败时立即恢复两套运行时快照并尝试重写原值，界面保持编辑状态并显示失败提示。底层文件系统持续不可写时仍会明确显示失败，不能报告应用成功；运行时必须恢复，磁盘重写失败则由错误状态明确暴露。
- `AccessibilityPreferencesService.Changed`是运行时统一通知。UI不得逐帧轮询文件。

## UI接入契约

- 普通`UnityEngine.UI.Text`可挂载`AccessibleTextScale`，以组件首次启用时记录的字体大小为100%基准；布局必须允许150%字号下重排或扩展，不能只放大字形后裁切。
- 颜色需要随高对比模式切换的`Graphic`可挂载`HighContrastGraphic`，颜色由资源所有者显式配置。
- 状态不得只靠颜色表达。`NonColorStateCue`允许状态所有者同时切换两个不同形状、图标或文字标记；标记内容仍由本地化/UI所有者提供。
- 暂停菜单的所有按钮、滑杆和滚动条通过白色边缘标记显示键盘焦点，不依赖高亮颜色；设置保存失败使用本地化文字并带`⚠`形状标记。
- 动画、闪烁、循环粒子或镜头表现的所有者通过`AccessibilityMotionPolicy`读取减弱动态偏好。减弱动态不得改变碰撞、计时、危险判定、镜子/镜像状态或谜题结果。
- 本基础层不自行推断哪些玩法反馈可以删除；重要危险与交互反馈必须保留静态或低动态替代提示。
- 当前接入覆盖环境Sprite呼吸、MirrorClone可读性光环、喷发警告/危险表现、风柱纹理漂移与脉冲、传送带标记滚动、冻结高阶段脉冲、风力涡轮旋转、地面火焰投掷者蓄力缩放与目标脉冲。减弱动态时停止或固定这些装饰循环，同时保留静态亮度、轮廓、方向标记、目标标记、蓄力标记和危险核心，不改变阶段计时、碰撞、速度或判定。风柱以双带/上带/下带区分吹风、平静与警告；传送带以方向标记存在或隐藏区分启用与停用；风力涡轮停用时恢复初始角度。
- `RisingLava2D`在Warning阶段使用熔岩Sprite变亮传达预警，不创建额外的白色三角轮廓；该表现不改变Trigger位置或阶段计时。
- `SnowmanGate2D`为现有Prefab运行时创建白色形状提示：等待胡萝卜时显示`X`，满足后显示勾形；颜色/透明度仍可辅助表达，但不再是唯一状态线索。形状切换不参与Collider、阻挡、重置或存档逻辑。
- 世界空间`RoomExitLabel2D`按文字缩放偏好调整`TextMesh.characterSize`，高对比时使用白色；本地化文字与字体选择仍由原服务负责。
- 原型`MirrorPlatformerBootstrap.OnGUI`按文字缩放设置字号，高对比时提供黑色底板与白字，并用`Screen.safeArea`和实际像素宽度进行换行与定位，不再依赖固定左上坐标和宽度。

### 审计列表中的保留项

- `RisingLava2D`的升降仍是危险Trigger本身的玩法位置和阶段计时，不能因减弱动态而减速、停止或插值替换；Warning阶段只调整熔岩Sprite颜色，不缩放Sprite，也不改变危险边界。
- `WindRayEnemy2D`没有独立装饰循环：目标标记、Dash轨迹和朝向均直接表达实际锁定点、运动位置和攻击状态。减弱或延迟它们会隐藏关键危险信息，因此保持原样；其目标标记和轨迹已经提供非颜色线索。
- `GroundFireThrowerEnemy2D`的实际投射物轨迹与攻击计时保持不变，只固定蓄力和目标标记的表现缩放。

## Canvas、安全区域与响应式布局

- 可复用屏幕空间Canvas挂载`ResponsiveCanvasScaler`，统一使用`Scale With Screen Size`、`1920×1080`参考分辨率、宽高匹配值`0.5`。
- Canvas下的全屏内容容器可挂载`SafeAreaFitter`。它把`Screen.safeArea`换算为归一化锚点，并在屏幕尺寸或安全区域变化时刷新。
- 暂停设置面板使用`ResponsivePanelFitter`：根据当前屏幕、Canvas `0.5`缩放和安全区域计算逻辑尺寸，并在`1040×1000`上限内保留每边至少32逻辑像素。标题、滚动内容、返回按钮、提示和失败状态都属于该面板布局，不会伸出安全区域。
- 交互内容使用锚点与Layout Group，不依赖只对16:9成立的固定绝对坐标。
- 文本容器必须允许换行/扩展；关键按钮、当前焦点、错误状态和操作提示不得被安全区域或屏幕边缘裁切。
- 本UI缩放契约不改变世界相机的正交尺寸、房间边界或构图。世界可见性仍以`CAMERA_SYSTEM.md`为权威来源。

## 验证矩阵

| 分辨率 | 比例 | 用途 |
|---|---|---|
| 1280×720 | 16:9 | 低分辨率验证 |
| 1920×1080 | 16:9 | 参考档位 |
| 2560×1440 | 16:9 | 高分辨率验证 |
| 2560×1080 | 21:9 | 超宽验证 |
| 3440×1440 | 约21:9 | 高分辨率超宽验证 |
| 1920×1200 | 16:10 | 纵向空间较多的宽屏验证 |
| 1024×768 | 4:3 | 验证档位（非最低支持声明） |

每个档位需分别检查100%、125%、150%文本缩放，共21种基础“分辨率×字号”组合，并逐项检查高对比开关。减弱动态必须以时间证据检查，不可仅用截图证明。窗口/全屏切换后需重新检查安全区域、焦点、裁切和相机构图。

## 现有系统接入清单

- 设置菜单：已增加三项偏好控件，使用`AccessibilityPreferencesService`读写；保存失败提供本地化文字与非颜色标记，不把偏好塞入游戏进度存档。
- UI所有者：给全部玩家可见文本接入`AccessibleTextScale`或等价适配；在验证矩阵的21种“分辨率×字号”组合中检查换行、遮挡、滚动和焦点。
- 本地化所有者：按钮、状态标记和错误信息继续来自本地化表；验证所有正式语言在150%字号下的展开长度。
- 表现所有者：为装饰循环、闪烁、屏幕震动和快速过渡读取`AccessibilityMotionPolicy`，提供不改变玩法结果的静态/低动态替代。
- 玩法/UI所有者：门、开关、危险、成功、失败和选中状态至少同时具有形状、图标、文字或运动中的一种非颜色线索。
- 相机/关卡所有者：在七个验证档位下复核完整视野边界、Player/MirrorClone和关键因果对象可见性；不得用UI适配器改写房间相机规则。

## 尚未批准或未实现

- 最低支持分辨率尚未声明。
- 字幕/封闭字幕范围、屏幕阅读器语义、手柄导航和新的输入辅助规则不由本基础实现推断。
- 尚未把组件挂入Scene、Prefab或暂停菜单以外的其他运行时UI；这些资源需要按所有权逐步接入。
