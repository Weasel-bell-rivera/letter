# 水平火球投掷敌人设计

## 状态与审批边界

- 建议玩法名称：投火者。
- 建议实现名称：`HorizontalFireballEnemy2D`。
- 区域归属：火之区域。
- 当前状态：**设计已由用户确认；运行时代码、共享配置、敌人与火球Prefab均已生成，尚未进行PlayMode试玩验证**。
- 本文定义一种全新敌人及其独立火球，不复用或修改逐风鳐行为。
- 已确认规则已同步到火区、敌人、重置和Prefab目录权威文档。
- 通用机制与Prefab已经批准；用户随后明确批准`FIRE_002`作为首次正式教学房，具体布局与实例配置见对应房间文档。

## 设计目标

投火者制造稳定、可预判的水平威胁。它观察自身左右两侧的水平攻击带，在Player或MirrorClone进入时选择目标，经过明确蓄力后向目标所在方向发射一枚水平飞行的火球。

主要谜题价值：

- Player与MirrorClone可以从不同方向或不同高度改变谁会成为目标。
- 玩家可以让MirrorClone吸引火球，为Player制造通过窗口。
- 火球方向与节奏在发射前可判断，不依赖反应速度或随机数。

首版不包含抛物线、弹道下坠、自动追踪、连射、散射、弹跳、爆炸范围、点燃、熔化或持续燃烧。这些都属于额外规则，不能由房间实例自行开启。

## 对象结构

建议创建两个通用Prefab：

```text
HorizontalFireballEnemy2D
├─ Visual
│  ├─ BodyVisual
│  └─ MuzzleVisual
├─ BodyCollider
├─ DamageTrigger
└─ FireOrigin

HorizontalFireballProjectile2D
├─ Visual
└─ DamageTrigger
```

建议路径：

- `Assets/Prefabs/Gameplay/Enemies/HorizontalFireballEnemy2D.prefab`
- `Assets/Prefabs/Gameplay/Enemies/Projectiles/HorizontalFireballProjectile2D.prefab`

敌人负责感知、选敌、蓄力、发射节奏和房间重置。火球负责固定方向移动、碰撞、命中和销毁。具体房间不得复制这两类逻辑。

- 敌人`BodyCollider`标准范围为`0.9 × 1 unit`；`DamageTrigger`范围为`1 × 1.1 units`并使用本地`Y=0.05`偏移，使两者底边完全齐平。固定落地实例以该共同底边贴合支撑面，不允许DamageTrigger向下陷入地形。

## 敌人状态模型

```text
Watching
   |
   | 水平攻击带内出现合格目标
   v
Windup
   |
   | 蓄力结束，生成一枚火球
   v
Cooldown
   |
   | 冷却结束
   +--------------------------> Watching
```

### `Watching`

- 敌人固定在房间显式配置的位置，不巡逻、不追踪目标。
- 每个固定物理步检查Player与当前存在的MirrorClone。
- 没有合格目标时不蓄力、不发射。
- 敌人身体接触伤害保持启用。

### `Windup`

- 进入状态时确定目标种类和发射方向，只记录方向，不记录需要追踪的目标位置。
- 蓄力期间不重新选择目标，也不因另一角色更近而改变方向。
- 目标移动、死亡、被遮挡或MirrorClone被回收，都不取消本次发射。
- 蓄力期间通过身体变亮、朝发射口聚集火焰和声音提示攻击即将发生。
- **不显示红色小叉、准星、落点标记或攻击终点标记。**

### `Cooldown`

- 发射后进入固定冷却时间。
- 冷却期间不选取新目标，也不提前发射。
- 冷却结束后回到`Watching`；若目标仍满足条件，可以开始下一轮蓄力。
- 同一敌人在首版同时最多保有一枚自己发射且尚未销毁的火球；火球仍存在时，即使冷却结束也等待其销毁后再开始下一轮。

## 感知与目标选择

### 水平攻击带

- 感知使用显式数值定义的世界空间水平矩形，不从Tile、Collider边界、Sprite、对象名称或房间编号推断。
- 攻击带以`FireOrigin`为中心，同时覆盖左右两侧。
- 首版半宽`6 units`，总宽`12 units`；半高`0.75 units`，总高`1.5 units`。
- 使用角色主Collider的中心点判断其是否进入攻击带。
- 静态实体地形和完全关闭的门阻挡感知；镜子不阻挡感知，也不是目标。
- 感知区域不在游戏中绘制边框或精确量尺，只允许Editor Gizmo用于制作检查。

### 合格目标

- Player和MirrorClone具有相同目标资格。
- 只有中心位于水平攻击带内，且与`FireOrigin`之间无遮挡的角色才合格。
- 两个角色都合格时，选择到`FireOrigin`水平距离更近的角色。
- 水平距离完全相同时选择Player，保证结果确定且不依赖对象查询顺序。
- 一旦进入`Windup`，本轮目标不再切换。

### 发射方向

- 目标中心位于`FireOrigin`右侧时向世界`+X`发射；位于左侧时向世界`-X`发射。
- 当目标与`FireOrigin`的水平差绝对值不超过`0.05 units`时，使用敌人实例配置的初始朝向。
- 初始朝向只能为左或右；房间不得通过旋转Transform生成竖直或斜向变体。

## 火球规则

### 生成与移动

- 蓄力完成时在`FireOrigin`生成一枚火球。
- 生成前检查完整火球Collider空间；若被静态实体、关闭的门、Player、MirrorClone或其他实体占用，本次发射失败并直接进入`Cooldown`，不得把占用者推出、临时关闭碰撞或改换生成点。
- 火球只沿生成时确定的世界`-X`或`+X`移动，世界`Y`保持不变。
- 火球使用Kinematic `Rigidbody2D`，在`FixedUpdate`中移动；结果不依赖渲染帧率。
- 火球速度固定为`8 units/s`，不受重力、传送带、移动平台或普通环境风力影响。
- 火球发射后不追踪、不转向、不加速，也不因为目标消失而停止。

### 碰撞与销毁

- 火球命中静态实体地形或完全关闭的门时立即销毁。
- 火球命中Player时，先消费并销毁火球，再触发完整房间死亡重置。
- 火球命中MirrorClone时，先消费并销毁火球，再触发镜像死亡与镜子自动回收；Player和房间不整体重置。
- 火球穿过已放置镜子；不阻挡、不推动也不破坏镜子。
- 火球不触发普通`Occupancy`压力板、其他Trigger、拾取物、出口或复活点，不推动动态对象。唯一机关例外是显式配置为`FireballLatch`的`PressurePlate2D`：命中后压力板锁存激活，火球立即销毁。
- 首版火球不伤害敌人，不与其他火球碰撞，也不被Player或MirrorClone反弹。
- 火球离开当前相机可显示边界外`1 unit`，或存活达到`2 seconds`时销毁，以先发生者为准。
- 火球销毁不产生爆炸伤害、残留火焰或地形变化。

### 伤害一致性

- 火球对Player和MirrorClone使用与通用敌人一致的死亡分流。
- 敌人本体Damage Trigger接触Player时触发完整房间重置；接触MirrorClone时只执行镜像死亡联动。
- 敌人本体和火球都不破坏镜子。

## 表现与可读性

- 敌人身体轮廓应明显展示固定的水平发射口，并根据当前或初始朝向左右翻转。
- `Watching`保持暗红或暗橙待机火光。
- `Windup`在`0.6 seconds`内逐步变亮，并让火焰向发射口收拢；同时播放短促升调音效。
- 发射瞬间提供火光闪烁和清晰发射声。
- `Cooldown`期间发射口变暗，向玩家表达暂时不会再次攻击。
- 火球使用高亮橙黄色主体与短水平拖尾；视觉边界不得明显小于伤害Collider。
- 不使用红色小叉或任何世界空间目标点标记。
- 反馈不能只依赖颜色；蓄力、发射和冷却至少同时具有轮廓/动画变化。

## 首版统一数值提案

| 参数 | 提案值 |
|---|---:|
| 水平攻击带半宽 | `6 units` |
| 水平攻击带半高 | `0.75 units` |
| 蓄力时间 | `0.6 s` |
| 发射冷却 | `1.4 s` |
| 同时存在火球上限 | `1` |
| 火球速度 | `8 units/s` |
| 火球最大寿命 | `2 s` |
| 离开相机边界销毁余量 | `1 unit` |
| 同X方向判断容差 | `0.05 units` |
| 火球Collider建议尺寸 | `0.4 × 0.4 units` |

这些是敌人类型的共享数值，不允许正式房间逐实例覆盖。房间实例只允许配置位置、初始左右朝向和不改变玩法边界的视觉变化。

## 重置、死亡与场景切换

- 手动重置或Player死亡重置时，敌人恢复初始位置、初始朝向和`Watching`状态，清空目标、蓄力、冷却以及它生成的全部在途火球。
- MirrorClone单独死亡、镜子回收或镜子被破坏时，不重置敌人状态；若敌人已经进入`Windup`，仍按已记录方向发射。
- MirrorClone被该敌人的火球击中后，火球立即销毁，敌人保持当前`Cooldown`或其他当前阶段。
- 场景切换开始后停止发射并销毁旧房间全部在途火球；新房间不得收到旧场景延迟生成或对象池返回的火球。
- 敌人状态与火球属于`RoomAttemptState`，不写入长期存档。

## 房间使用约束

- 首次教学房必须让Player在攻击带外安全观察一次完整的蓄力、发射和冷却反馈。
- 敌人与入口之间不得形成无预警的水平直射线。
- 房间必须提供稳定的高度规避空间或实体掩体，不得要求帧级闪避。
- 使用MirrorClone诱导时，双方位置必须能稳定产生不同目标结果，不依赖像素级距离平局。
- 房间不得改变感知范围、选敌优先级、火球速度、生命周期、镜子交互或重置规则。
- 该机制已获准进入`FIRE_002`和既有`FIRE_009`正式Scene；`FIRE_002`承担首次教学，`FIRE_009`承担巩固练习。

## 实现结构提案

- 敌人、火球移动和伤害结算使用独立通用组件，表现层只读取状态，不决定玩法结果。
- 火球由敌人通过显式Prefab引用生成；不使用名称查找、`Resources`路径或房间编号选择Prefab。
- 固定放置在Scene中的敌人可直接使用通用Prefab。未来若运行时生成，必须另行遵守`docs/systems/ENEMY_SPAWN_SYSTEM.md`，本提案不定义Spawner策略。
- 首版使用Instantiate/Destroy即可；对象池只允许作为不改变行为的内部优化，并必须清空速度、伤害占用和生命周期状态。

## 验收标准

- Player与MirrorClone按相同资格进入水平攻击带，并按水平距离与平局规则确定目标。
- 敌人蓄力期间不切换目标，且全程不出现红色小叉或落点标记。
- 火球只水平移动，不受重力、不追踪、不穿过静态实体和关闭的门。
- 火球分别对Player和MirrorClone执行正确的死亡流程，并在命中时只结算一次。
- 镜像死亡或镜子回收不会取消已经锁定的发射，也不会重置敌人。
- 手动重置、Player死亡和场景切换不会留下火球、目标、速度、计时或事件引用。
- 敌人和火球不破坏镜子、不修改Tilemap，也不依赖具体房间逻辑；火球只允许触发通用`FireballLatch`压力板，不响应房间专用机关。

## 已确认结论

用户已确认：

1. 敌人固定不动，只向左右发射独立水平火球。
2. 只有位于`1.5 units`高水平攻击带内且无遮挡的Player/MirrorClone能触发攻击。
3. 两者同时合格时选择水平距离最近者，平局选择Player。
4. 蓄力锁定方向后不追踪目标，并且不显示红色小叉或替代落点标记。
5. 火球碰实体销毁；命中Player重置房间，命中MirrorClone只杀死镜像并回收镜子。
6. 首版统一数值采用本文表格，且不允许房间实例覆盖。
7. 通用敌人和火球Prefab的初次实现未加入正式房间；后续用户另行批准将其加入`FIRE_002`并把该房设为首次教学房。
