# 巡逻投火者设计提案

## 状态与边界

- 建议玩法名称：巡逻投火者。
- 建议实现名称：`PatrollingHorizontalFireballEnemy2D`。
- 区域归属：火之区域。
- 当前状态：**设计已由用户确认并纳入火区正式规则；运行时代码、共享配置、通用Prefab和独立测试Scene已生成，尚未进行PlayMode试玩验证，也未指定正式教学房**。
- 本敌人以`HorizontalFireballEnemy2D`的水平索敌、蓄力、发射、火球碰撞、伤害和重置规则为基础，新增确定性的水平地面巡逻。
- 水平巡逻改变了原投火者“固定守卫”的核心移动模型，因此它是独立敌人原型和独立基础Prefab，不是原Prefab的房间开关或Prefab Variant。

## 设计目标

巡逻投火者让水平火线的发射位置随时间变化。玩家需要同时判断敌人的巡逻方向、下一次停火位置以及Player和MirrorClone谁会进入攻击带。

设计必须满足：

- 移动、转向和攻击不使用随机数。
- 玩家在行动前可以从朝向、移动和蓄力反馈判断下一步行为。
- Tile只提供静态几何和表面语义；敌人不得根据Tile、Sprite、Tilemap或GameObject名称判断阻挡。
- 房间不能通过专用脚本改变巡逻、索敌或火球规则。

## 与投火者共享的规则

除本文明确修改的移动与状态规则外，以下行为完全继承`docs/systems/HORIZONTAL_FIREBALL_ENEMY_PROPOSAL.md`：

- 世界空间`12 × 1.5 units`水平攻击带。
- Player和MirrorClone的目标资格、无遮挡判定、最近目标优先和平局选择Player。
- 蓄力开始后只锁定世界左或右，不继续追踪目标。
- `0.6 s`蓄力、`1.4 s`冷却、`8 units/s`水平火球和同一敌人最多一枚在途火球。
- 火球命中实体阻挡后销毁；命中Player执行完整房间重置，命中MirrorClone只执行镜像死亡与镜子回收。
- 火球与镜子、门、压力板、动态对象、相机边界和场景切换的全部既有规则。
- 敌人本体接触Player或MirrorClone时沿用通用敌人伤害分流。

原`HorizontalFireballEnemy2D`继续固定不动，其现有Prefab、房间实例和行为不得被本提案改变。

## 状态模型

```text
Patrolling
   |
   | 攻击带内出现合格目标
   v
Windup（停止移动）
   |
   | 蓄力结束并发射
   v
Cooldown（停止移动）
   |
   | 冷却结束且在途火球已销毁
   +--------------------------> Patrolling

任意活动状态 -- 前方阻挡 --> TurnPause --> 反向 --> 原活动状态
```

### `Patrolling`

- 敌人以固定速度沿世界`-X`或`+X`移动，不追逐Player或MirrorClone。
- 移动只在固定物理步中通过Dynamic `Rigidbody2D`设置水平速度执行，竖直速度由重力和碰撞独立结算。
- 当前移动方向同时作为没有目标时的视觉朝向。
- 检测到合格目标后立即停止水平移动，进入`Windup`。

### `Windup`与`Cooldown`

- 两个攻击阶段都停止主动水平移动，但保留竖直重力运动；敌人在下落中仍可继续完成蓄力和冷却。
- `Windup`进入时锁定发射方向；敌人随后因目标消失、镜像回收或另一角色更近都不改变方向。
- 冷却结束且自己的在途火球已经销毁后，恢复进入攻击前的巡逻方向。
- 停止攻击期间仍执行前方实体阻挡检查；若门或其他合法实体在敌人前方关闭，先记录反向请求，恢复巡逻前完成转向。

### `TurnPause`

- 前方检测到有效实体阻挡时，敌人立即停止，不向阻挡内部持续施力。
- 默认停顿`0.2 s`后反向；停顿与方向变化不依赖碰撞回调顺序。
- 同一固定物理步中的多个前方阻挡只结算一次转向。
- 转向不得取消已经开始的`Windup`、销毁在途火球或改变已锁定的发射方向。

## Tile阻挡与地面检测

### 前方阻挡

- 敌人从身体前侧使用与实体Collider高度匹配的短距离BoxCast，查询下一固定物理步内的阻挡。
- `TilemapCollider2D`提供的Tile地形与独立Collider使用相同查询路径，只有显式表面语义为`StaticSolid`的静态实体地形才触发地形折返。
- 已完全关闭的普通门也视为前方实体阻挡；敌人停止并折返，不持续挤压门。
- Player、MirrorClone、镜子、其他Enemy、Trigger、压力板、拾取物、移动平台、传送带和装饰不作为“Tile阻挡”。
- 不得通过Tile名称、Sprite名称、Tilemap名称、GameObject名称、Layer名称或房间编号推断阻挡资格。

### 平台缺口与下落

- 敌人不进行前脚地面探测，平台边缘和地面缺口不触发转向。
- 离开支撑面后保持当前水平巡逻方向和速度，并由Dynamic `Rigidbody2D`的正常重力自然下落。
- 落到下一处实体表面后继续沿原方向巡逻；只有前方有效实体阻挡才触发`TurnPause`和反向。
- `Hazard`、`DynamicSurface`、`Conveyor`、门顶和只有视觉没有表面语义的Tile仍不作为前方静态阻挡语义。

## 移动与配置

房间实例只允许配置：

- 初始位置。
- 初始移动方向（左或右）。
- 是否启用攻击带的Editor可视化，仅用于制作检查且不进入运行时画面。

建议共享数值：

| 参数 | 建议值 |
|---|---:|
| 巡逻速度 | `1.5 units/s` |
| 重力倍率 | `1` |
| 转向停顿 | `0.2 s` |
| 前方阻挡探测余量 | `0.08 unit` |

这些数值应保存在共享Settings资产中，不允许具体房间逐实例覆盖。正式巡逻路线由房间的实体地形约束，不从房间编号或自动扫描结果生成，也不设置隐藏的随机端点。

首版不包含跳跃、攀墙、追逐、加速、被角色推动、走上移动平台或搭乘传送带。敌人只会通过重力从缺口或平台边缘落到更低表面，不主动寻路或选择落点。

## 碰撞、攻击与可读性

- 敌人保留与原投火者一致的实体Collider、Damage Trigger、FireOrigin和火球尺寸。
- 敌人不能持续推动、挤压或夹住Player与MirrorClone；房间必须在完整巡逻路线周围预留角色安全空间。
- 移动时播放连续步行动画或身体起伏；`TurnPause`具有短促停步和明确翻面。
- `Windup`继续使用原投火者的变亮、发射口聚火和声音反馈，同时停止脚步表现。
- 发射方向由锁定目标决定，可以与恢复巡逻后的移动方向不同；身体/发射口在蓄力时朝向发射方向，冷却结束后再朝向巡逻方向。
- 反馈不能只依赖颜色，且不得显示红色小叉、准星或落点标记。

## 重置、死亡与场景切换

- 手动重置或Player死亡重置时，敌人恢复初始位置、初始巡逻方向和`Patrolling`状态，清空转向停顿、目标、蓄力、冷却、阻挡缓存和全部在途火球。
- MirrorClone单独死亡、镜子回收或镜子被破坏不重置敌人的位置、巡逻方向或攻击阶段；已经锁定的发射继续结算。
- 敌人被`FreezingGround`完全冻结时停止移动和攻击、销毁自己的在途火球并关闭本体伤害；冻结不会自动使它成为安全踏板。
- 场景切换不携带位置、方向、转向请求、目标、攻击阶段、计时或火球。
- 全部状态属于`RoomAttemptState`，不写入长期存档。

## 房间使用约束

- 首次教学房必须先让玩家在安全位置看到敌人完成一次遇墙折返，再要求处理其火球。
- 需要限制巡逻范围的一端必须使用清晰可见的实体墙；平台边缘会使敌人下落，不再充当折返点。
- 敌人进入攻击带前后的位置变化不能制造出生即命中或帧级闪避要求。
- 关闭的门可以临时改变折返位置，但门的防夹和关闭等待仍以`docs/systems/DOOR_SYSTEM.md`为准。
- 首版不与移动门、移动平台、传送带或运行时改变Tilemap的机制共用同一巡逻路线。
- 本提案不指定教学房、地图连接、Spawner或正式出口；批准后需另行更新区域房间索引与具体房间文档。

## 验收标准

- 敌人在连续静态地面上以固定速度左右移动，结果不依赖帧率或随机数。
- 前方遇到由Tilemap或独立Collider提供的`StaticSolid`阻挡时停止、短暂停顿并反向，不持续向墙内施力。
- 遇到平台边缘或地面缺口时保持当前水平方向并受重力下落，落地后继续巡逻。
- 移动、转向和攻击状态的组合不会造成双重转向、漂移发射点或锁定方向变化。
- 原固定投火者的Prefab、房间实例和行为保持不变。
- Player、MirrorClone、镜子、门、火球、冻结、重置和场景切换分别遵守既有通用规则。
- 行为不依赖Tile、Sprite、Tilemap、GameObject或房间名称，也不修改Tilemap。

## 已确认结论

用户已确认：

1. 巡逻投火者是独立敌人原型，继承固定投火者的索敌、蓄力、水平火球、伤害和镜子交互规则。
2. 敌人在连续安全静态地面上以`1.5 units/s`左右移动，遇到`StaticSolid` Tilemap或独立Collider阻挡时停止并折返。
3. 敌人在平台边缘或地面缺口处不折返，保持当前水平方向并受正常重力下落；落地后继续巡逻。
4. 转向停顿采用`0.2 s`；移动、转向和攻击均不使用随机数。
5. `Windup`和`Cooldown`期间停止主动水平巡逻但继续受重力；已锁定发射方向不因转向请求、目标消失或镜像回收改变。
6. 该机制批准进入火区正式规则，但本次批准不指定或修改任何正式房间，也不自动批准实现或耗时测试。
