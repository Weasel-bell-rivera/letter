# 存档系统

## 文档职责

本文定义长期存档内容、写入时机、读取流程、故障恢复、版本迁移和测试标准。区域顺序与解锁条件仍以 `docs/maps/WORLD_PROGRESSION.md` 为准。

## 设计目标

- 永久进度在死亡、重置、切换房间、退出和升级版本后可靠保留。
- 房间瞬时状态不会错误进入长期存档。
- 写入中断或文件损坏时存在恢复路径。
- Scene不直接操作磁盘，只通过统一存档服务提交状态变化。

## 状态分层

| 层级 | 生命周期 | 示例 | 长期保存 |
|---|---|---|---|
| `RoomAttemptState` | 本次房间尝试 | 普通门、普通压力板、未锁存门控组、临时道具、镜子放置、MirrorClone、敌人位置、巡逻阶段、冻结或墙面接触状态、传送带启用与接触状态 | 否 |
| `RoomSessionState` | 本次停留房间 | 当前复活点 | 否 |
| `ProfileState` | 当前进度档 | 能力、永久收藏、区域进度、永久锁存门控组、继续位置 | 是 |
| `SettingsState` | 本机设置 | 音量、画面、键位、辅助功能 | 单独保存 |

不得整体序列化Scene或运行时对象。

## 首版存档结构

```text
SaveData
  schemaVersion
  saveId
  createdAtUtc
  updatedAtUtc
  playTimeSeconds
  lastRoomId
  lastEntranceId
  unlockedAbilities[]
  collectedPermanentIds[]
  completedRoomIds[]
  unlockedRegionIds[]
  latchedDoorGroupIds[]
  regionProgress[]
  progressionFlags[]
```

- `schemaVersion` 用于迁移，`saveId` 是存档的稳定唯一ID。
- 时间戳使用UTC；游玩时间只统计未暂停且玩家可操作的时间。
- `lastRoomId` 必须是地图中的有效房间；入口无效时回退到该房间默认入口。
- 镜子能力记录在 `unlockedAbilities`，对应永久拾取ID也记录在永久ID集合中。
- 镜子的稳定能力ID为`MIRROR`，对应拾取ID为`CENTER_001:ABILITY:01`。
- `collectedPermanentIds`包含永久能力、永久收藏品和进度物的全部拾取ID。
- 如果读取时仅存在镜子拾取ID或`MIRROR`能力ID之一，按两者的并集恢复能力和领取状态，并请求写回修复后的存档。
- 房间完成、区域解锁和进度标记只能记录已获批准的规则。
- `latchedDoorGroupIds`记录已经永久锁存的双压力板门控机关组；元素是稳定且全游戏唯一的`DoorGroupId`，按唯一值处理。
- 机关组首次锁存时立即把组ID加入`latchedDoorGroupIds`并请求写入。已有ID不得重复添加或重复播放首次锁存流程。
- 集合字段按唯一值处理，不依赖数组顺序表达逻辑。
- `regionProgress[]`的首版元素为`regionId`、`collectedCount`和`totalCount`，只表达收藏完成度，不隐含区域完成或解锁规则。

## 不保存的内容

- Player精确坐标、速度、当前复活点和临时运动状态。
- 镜子的放置位置、朝向及MirrorClone状态。
- 普通门、普通压力板、未锁存门控组、Trigger、移动平台、地面传送带和危险物的瞬时状态。
- 地面巡逻、竖直墙面巡逻、活动或冻结敌人的位置、方向、巡逻阶段、等待计时、接触引用、墙面接触和冻结状态。
- Player与MirrorClone的寒冰表面运动状态。
- Player与MirrorClone的传送带支撑引用和已施加表面速度。
- 失重之羽及其他本次房间尝试的临时效果。

读取后，Player从记录入口或安全默认入口出现；普通房间机关按初始状态创建；`latchedDoorGroupIds`中的机关组直接恢复为门完全开启、两块压力板保持按下；镜子若已解锁则回到Player手中。

## 新游戏

1. 创建默认数据并生成 `saveId`。
2. 起点设置为 `CENTER_001` 的新游戏出生点。
3. 初始能力、收藏和区域进度为空。
4. 请求首次写入，再加载起点；写入失败时保留内存状态并重试。
5. Player按 `CENTER_001` 房间文档获得镜子。

首版采用单一存档。标题界面的“新游戏”在已有进度时必须二次确认，确认后才可保留旧文件供故障恢复并创建新存档。

## 读取与继续

1. 读取并校验主存档；失败则读取备份。
2. 旧版本按顺序迁移并再次校验。
3. 先把长期状态载入内存，再加载目标房间。
4. 无效入口回退到房间默认入口；无效房间回退到 `CENTER_001`。
5. 初始化能力、收藏和永久进度，房间瞬时状态使用初始值。

加载房间中的永久锁存门控组时，必须先完成存档有效性校验，再向对应`DoorGroupId`应用锁存状态；存档中不存在的旧组ID应记录警告并安全忽略，不能阻止存档读取。

“继续游戏”从最近一次成功进入房间时记录的入口恢复；入口无效时使用该房间安全默认入口，房间无效时回退到`CENTER_001`新游戏出生点。

存档有效性尚未确定前，不得让Player开始操作或开放永久拾取物交互。

## 自动存档触发点

- 获得永久能力、收藏品或进度物。
- 房间首次完成。
- 区域解锁、完成或其他已批准永久进度变化。
- 双压力板门控机关组首次进入永久锁存状态。
- 成功切换到另一个房间后，更新继续游戏位置。
- 安全退出到标题画面或关闭游戏时再次保存。

连续请求可以合并，但最终数据必须包含所有已经提交到内存的变化；退出保存不能成为永久进度的唯一保障。

## 原子写入与备份

首版使用本地文件：

1. 将完整数据写入临时文件。
2. 重新读取并校验临时文件。
3. 保留上一份有效主文件作为唯一备份。
4. 原子替换主文件。
5. 成功后才标记磁盘同步完成。

不得直接分段覆盖主文件。首版单档固定使用一个主文件、一个临时文件和一个备份文件，且不得保存密码或令牌。

## 失败与损坏恢复

- 永久进度先提交内存，写入失败不回滚奖励、不重新生成对象。
- 保持“未同步”状态并自动重试；场景切换不得丢弃待写入变化。
- 玩家退出时仍写入失败，必须明确提示并允许重试。
- 主文件损坏时自动尝试备份；恢复成功后提示玩家。
- 主文件与备份都无效时不得静默覆盖；保留损坏文件，并让玩家选择新建存档或返回标题。
- 日志只记录存档标识、阶段和错误类型，不输出完整存档内容。

## 首版提示规则（已确认）

- 正常自动存档只显示短暂的非阻塞保存图标。
- 写入失败后后台安全重试；持续失败时显示明确错误提示和“重试”“返回标题”选项。
- 玩家选择返回标题前仍须再尝试一次写入；失败状态不得伪装成保存成功。
- 主文件由备份恢复成功时显示一次非阻塞恢复提示。

## 版本迁移

- 结构变化必须提高 `schemaVersion`。
- 使用逐版本迁移，例如 `v1 -> v2 -> v3`。
- 房间或收藏ID变化必须提供旧ID到新ID映射。
- 迁移前保留原文件；失败不得覆盖最后有效存档。
- 迁移后能力、收藏和区域进度不能倒退或重复发放。

## Unity实现边界

- 存档服务是跨Scene全局服务，房间Scene不得各自创建存档管理器。
- 玩法系统提交类型明确的状态变化，不直接访问路径或序列化器。
- 同一存档的写入请求必须串行，禁止并发覆盖。
- 存档DTO与MonoBehaviour分离，不保存Scene引用、实例ID或Transform。
- 文件位于Unity持久化数据目录；路径和文件名由存档服务统一生成。
- 编辑器检查或自动测试必须验证房间、收藏和区域ID唯一且有效。
- 首版只实现本地存档，文件根目录使用`Application.persistentDataPath`，不实现云存档。
- 首版可以提供房间、区域、全世界三级收藏统计查询接口，但正式统计UI不属于本次范围。
- `ProgressionItem`只提供数据与提交接口；世界进度规则批准前不得配置会解锁区域的实例。

## 与重置、切场景的关系

- 死亡和手动重置只恢复瞬时状态，不回滚永久进度。
- 已写入`latchedDoorGroupIds`的门控机关组在死亡、手动重置、切换房间和重新进入房间后仍保持锁存；只有开始新存档才清除。
- 当前复活点不写入长期存档。
- 切场景前清除镜像、回收镜子和交互占用；目标Scene加载成功后才更新继续位置。
- 目标加载失败时不得把该房间写成继续位置。
- 详细状态矩阵见 `docs/systems/RESET_SYSTEM.md`。

## 验收标准

- 新游戏从 `CENTER_001` 开始，初始没有镜子能力。
- 获得镜子后立即结束进程，重启仍能恢复能力。
- 永久收藏、房间完成和区域进度在重启后不倒退、不重复。
- 普通门、普通压力板、未锁存门控组、镜子放置、MirrorClone、临时效果和复活点不会跨重启恢复。
- 敌人的位置、巡逻阶段和冻结状态不会跨重启恢复；重新进入房间时按初始活动状态创建。
- 永久锁存门控组在锁存后立即请求写入，重启并读取存档后仍恢复为门开启、两块压力板保持按下。
- 新游戏不会继承旧存档的`latchedDoorGroupIds`。
- 主存档被截断时可从有效备份恢复。
- 模拟写入失败时不重复奖励，恢复写入能力后可成功重试。
- 旧版本样本可以迁移且原文件保留。
- 无效房间或入口不会把Player放进空Scene、墙内或危险区。
- 快速连续进度事件不会出现后写覆盖先写。

## 首版产品决定（已确认）

- 单一存档，不提供多档选择。
- 提供“新游戏/从头开始”；已有进度时必须二次确认。
- 继续游戏从最近成功进入房间时的入口恢复，失败时按安全回退链处理。
- 仅本地存档，不实现云存档。
- 自动保存、持续失败和备份恢复使用本文件定义的提示规则。
