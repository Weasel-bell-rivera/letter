# 相机系统

## 状态与权威范围

- 本文档是镜头比例、跟随构图、房间相机边界、固定单屏构图、镜头重置和场景切换表现的权威来源。
- Player移动物理仍以`docs/PLAYER_MOVEMENT.md`为权威来源；相机不得改变Player或MirrorClone的物理结果。
- 镜子放置、镜像生成和输入映射仍以`docs/MIRROR_MECHANIC.md`为权威来源；相机只负责呈现玩法信息。
- 房间文档可以配置镜头模式、边界和经过批准的构图例外，但不得重新定义通用相机行为。

## 设计目标

相机首先服务于玩法信息传达。

玩家应当能够在行动前观察移动目标、危险、镜子放置位置、MirrorClone路线和当前机关之间的关系，不得通过过近镜头制造盲操作。

镜头规则的优先级为：

1. 保证当前谜题因果关系清晰可见
2. 保证Player和MirrorClone可以稳定辨认
3. 为移动方向和跳跃方向提供观察空间
4. 保持角色视觉表现清晰
5. 服务环境氛围和场景构图

## 常规镜头比例

以下比例以`16:9`游戏画面为基准：

- Player站立时，可见角色主体高度应占屏幕高度的`12%–14%`。
- 默认设计目标为约`13%`。
- 屏幕纵向应能容纳约`7–8`个Player高度。
- 屏幕横向应能容纳约`13–15`个Player高度。
- 角色主体只计算站立状态的身体Sprite，不包含阴影、武器挥动、粒子、拖尾和临时受击特效。
- MirrorClone使用与Player完全相同的视觉尺寸和镜头可读性标准。

按照当前约`1.8 Unity unit`高的Player换算：

- 推荐正交镜头尺寸范围为`6.5–7.5`。
- 常规基准值为`7`。
- 该Unity参数属于当前资产尺度下的换算结果；Player视觉尺寸发生变化时，应优先保持占屏比例，而不是保留旧参数。

常规房间不得仅为突出美术细节而让Player占屏高度超过`14%`。

## 常规跟随构图

- 水平方向上，Player通常位于屏幕中央区域。
- 镜头可以向当前移动方向保留更多前方空间，但不得产生突然跳动。
- Player稳定站立时，角色中心通常位于屏幕从上向下约`50%–58%`的位置，为上方平台和跳跃路线保留更多空间。
- Player跳跃、下落或进行垂直移动时，镜头应保证落点、危险和下一处可到达表面能够提前进入视野。
- 镜头不得逐帧严格锁死Player位置；轻微移动、转向或落地不应造成抖动。
- 镜头追赶速度不得影响碰撞、输入、跳跃或其他玩法结果。

上述位置是常规跟随镜头的构图范围，不强制覆盖已明确设计为固定单屏的房间。

## 房间边界与停止跟随

每个正式房间必须明确配置相机可显示边界。该边界表示镜头允许显示的最大世界范围，不得根据Tile名称、Tilemap名称、GameObject名称或房间编号推断。

常规跟随镜头遵循以下规则：

- Player位于房间内部时，相机按照常规跟随规则移动。
- 当继续跟随Player会使镜头视野越过房间相机边界时，相机停留在边界位置。
- 相机停止后，Player仍可继续移动，并逐渐从屏幕中央移动到屏幕边缘区域。
- Player从房间边缘返回内部后，相机恢复跟随。
- 恢复跟随不得产生突然跳动、瞬间传送或明显抖动。
- 水平和垂直边界分别判断；触碰一个方向的边界不得阻止另一个方向的合法跟随。
- 相机视野不得显示房间边界之外的空白、未完成地形或相邻房间内容。
- Player、MirrorClone或其他玩法对象不得把镜头拉出当前房间边界。
- 镜头震动和临时表现也不得暴露房间边界之外的区域。

边界限制作用于整个相机视野，而不是相机中心点。

以矩形相机边界为例，相机中心的合法范围为：

- 最小X：房间左边界加相机视野半宽
- 最大X：房间右边界减相机视野半宽
- 最小Y：房间下边界加相机视野半高
- 最大Y：房间上边界减相机视野半高

因此，相机停止时应保证视野边缘与房间相机边界对齐。

如果房间尺寸小于当前完整视野：

- 相机使用固定构图并在对应方向居中显示房间。
- 不得仅为填满屏幕而自动放大镜头。
- Player占屏比例仍应遵循全局镜头规范。
- 房间边界之外的区域必须通过统一的背景延伸或遮挡方式处理，不得暴露未完成内容。

## 镜子与MirrorClone可见性

- 放置镜子前，玩家必须能够观察放置表面及镜像预计出现的主要空间。
- 镜子成功放置后，镜头不得因为生成MirrorClone而突然缩放或跳转。
- 谜题要求同时控制Player与MirrorClone时，镜头应尽量同时显示Player、镜子、MirrorClone及当前受影响的压力板、门、危险或目标。
- 不得将MirrorClone送出可观察区域后要求玩家依靠猜测完成精确操作。
- 如果单一跟随镜头无法清楚呈现上述关系，应调整房间布局、采用固定房间镜头或使用经过批准的通用取景方案，不能在房间脚本中临时改变镜像规则。

## 固定单屏房间

固定单屏镜头允许突破常规角色位置，但必须满足：

- 当前谜题的入口、操作对象、结果对象和主要失败路径同时可见。
- Player占屏高度原则上仍保持在`12%–14%`。
- 房间边界不得出现没有玩法意义的大面积空白。
- HUD不得遮挡出口、危险、压力板、门或镜子放置提示。
- 房间文档必须记录固定镜头尺寸、Player初始构图位置及采用固定镜头的原因。

如果房间确实需要超出常规比例，必须在房间文档中明确记录例外及其玩法理由。

## 死亡、重置和场景切换

- Player死亡重置后，相机必须回到复活位置对应的正确构图。
- 重置不得保留死亡前的追踪偏移、临时缩放或镜头震动。
- MirrorClone死亡或镜子被回收时，不得遗留以已销毁对象为目标的构图状态。
- 场景切换时必须先采用目标房间的相机边界，不得短暂显示新房间边界之外或旧房间的位置。
- 镜头表现不得延迟房间重置或改变玩法状态恢复顺序。

## 画面比例适配

- `16:9`是镜头比例和构图验收的基准画面比例。
- 在其他受支持的画面比例下，必须根据实际视野重新计算相机视野半宽和半高，不得直接复用`16:9`的边界钳制结果。
- 画面比例变化不得使Player占屏高度超出常规目标，也不得裁掉当前谜题的关键因果对象。
- 更宽画面可以显示更多横向环境，不得通过额外放大角色抵消新增视野。

## 房间设计要求

每份正式房间文档必须记录：

- 镜头模式：固定单屏或常规跟随
- 是否使用全局默认比例
- 相机可显示边界
- 必须同时进入视野的玩法对象
- 允许的构图边界
- 是否存在经过批准的镜头例外及其理由

房间不得通过修改Player尺寸来满足镜头构图。

## 验收标准

至少在`16:9`画面下验证：

- Player站立时占屏高度为`12%–14%`。
- Player和MirrorClone都能清楚辨认。
- 进入危险前能够观察危险及安全落点。
- 当前谜题的操作对象与结果对象可以建立明确视觉联系。
- 放置、回收及重复尝试镜子时镜头不跳动。
- Player分别走到房间左、右、上、下边缘时，相机在正确位置停止。
- 相机停止后Player仍能正常移动，不会被相机边界改变物理结果。
- Player返回房间内部时相机平滑恢复跟随。
- 相机在房间边缘不会显示房间外内容。
- Player死亡、MirrorClone死亡、手动重置和场景切换后构图及相机边界正确。
- 固定单屏房间没有被HUD遮挡的关键玩法对象。
- 在所有受支持的画面比例下重新验证视野边界和关键对象可见性。
