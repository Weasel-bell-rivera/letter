# 相机系统

## 状态与权威范围

- 本文档是镜头比例、跟随构图、房间相机边界、固定单屏构图、镜头重置和场景切换表现的权威来源。
- Player移动物理仍以`docs/PLAYER_MOVEMENT.md`为权威来源；相机不得改变Player或MirrorClone的物理结果。
- 镜子放置、镜像生成和输入映射仍以`docs/MIRROR_MECHANIC.md`为权威来源；相机只负责呈现玩法信息。
- 房间文档可以配置镜头模式、边界和经过批准的构图例外，但不得重新定义通用相机行为。

## 设计目标

相机首先服务于玩法信息传达。

玩家应当能够在行动前观察移动目标、危险、镜子放置位置、MirrorClone路线和当前机关之间的关系，不得通过过近镜头制造盲操作。

镜头规则的优先级为：

1. 保证当前谜题因果关系清晰可见
2. 保证Player和MirrorClone可以稳定辨认
3. 为移动方向和跳跃方向提供观察空间
4. 保持角色视觉表现清晰
5. 服务环境氛围和场景构图

## 所有权、层级与运行时目标

正式房间采用“房间拥有相机，Player作为运行时目标”的结构：

```text
Room Scene
├─ RoomSystems
│  └─ RoomPlayerSpawner2D
└─ Main Camera
   ├─ Camera
   └─ CameraFollow2D

运行时生成
Player
└─ CameraTarget（需要独立构图锚点时才添加）
```

- `Main Camera`及`CameraFollow2D`属于房间Scene，不属于Player Prefab，也不得成为Player的子对象。
- Player或经过批准的`CameraTarget`只作为`CameraFollow2D`的运行时跟随目标，不拥有相机规则。
- 房间Scene不得序列化引用运行时Player；`CameraFollow2D.target`在Scene资产中必须为空。
- `RoomPlayerSpawner2D`必须在Scene中显式引用本房唯一的`CameraFollow2D`。运行时查找只允许作为旧灰盒迁移兼容，不是正式房间配置方式。
- Player生成并通过安全空间检查后，Spawner绑定当前Player目标，先应用房间构图和边界并立即对准，再恢复Player输入。
- 相机只跟随Player目标。MirrorClone、镜子、门、压力板和敌人不得自行替换跟随目标或拉动相机；需要同时展示时通过房间布局、固定镜头或已批准的通用取景方案解决。
- 固定单屏房间仍在Scene中拥有相机及显式边界，但不建立Player跟随目标；不得通过把相机挂到静态占位对象来伪造固定镜头。

每个房间Scene是相机实例配置的权威资源。Editor Builder可以创建一次性灰盒或标准层级，但不得成为正式房间的第二份权威来源，也不得在房间进入运行时生成、替换或重新配置相机。

## 相机配置与绑定职责

通用相机行为与房间实例参数必须分离：

- `CameraFollow2D`统一实现目标跟随、阻尼、完整视野边界钳制和重置对准。
- 房间实例显式配置镜头模式、正交尺寸、跟随轴、构图偏移、阻尼和显示边界。
- `RoomPlayerSpawner2D`只负责把本次生成的Player绑定为目标，不得在运行时改写房间的正交尺寸、跟随轴、阻尼、构图偏移或边界。
- 构图偏移表示“相机中心相对于目标的位置”，必须作为房间参数显式保存；正式房间不得根据绑定瞬间相机与Player的Transform位置差推断偏移。
- 不跟随的轴由房间Scene中明确记录的相机固定中心坐标决定。跟随一个轴不得让另一个轴漂移。
- 目标绑定、目标解除和重新绑定不得保留上一目标的速度、临时偏移或推断结果。
- 平滑追赶在`LateUpdate`执行；立即对准用于初次进入、死亡重置、手动重置和明确要求无过渡的入口切换。

当前灰盒Scene允许在迁移期间保留旧式运行时查找或初始Transform偏移推断，但迁移完成时必须改为显式引用和显式构图，并由资产测试阻止回退。

## 常规镜头比例

以下比例以`16:9`游戏画面为基准：

- Player站立时，可见角色主体高度应占屏幕高度的`12%–14%`。
- 默认设计目标为约`13%`。
- 屏幕纵向应能容纳约`7–8`个Player高度。
- 屏幕横向应能容纳约`13–15`个Player高度。
- 角色主体只计算站立状态的身体Sprite，不包含阴影、武器挥动、粒子、拖尾和临时受击特效。
- MirrorClone使用与Player完全相同的视觉尺寸和镜头可读性标准。

按照当前约`1.8 Unity unit`高的Player换算：

- 推荐正交镜头尺寸范围为`6.5–7.5`。
- 常规基准值为`7`。
- 该Unity参数属于当前资产尺度下的换算结果；Player视觉尺寸发生变化时，应优先保持占屏比例，而不是保留旧参数。

常规房间不得仅为突出美术细节而让Player占屏高度超过`14%`。

## 常规跟随构图

- 水平方向上，Player通常位于屏幕中央区域。
- 镜头可以向当前移动方向保留更多前方空间，但不得产生突然跳动。
- Player稳定站立时，角色中心通常位于屏幕从上向下约`50%–58%`的位置，为上方平台和跳跃路线保留更多空间。
- Player跳跃、下落或进行垂直移动时，镜头应保证落点、危险和下一处可到达表面能够提前进入视野。
- 镜头不得逐帧严格锁死Player位置；轻微移动、转向或落地不应造成抖动。
- 镜头追赶速度不得影响碰撞、输入、跳跃或其他玩法结果。

### 出生定位与立即跟随（2026-09-15用户确认）

- 新出生、重新进入房间、绑定新的Player或死亡/手动重置后，相机在恢复玩家输入前立即对准当前Player，随后正常跟随；不再等待玩家跨越Scene中保存的初始构图线。
- 对准使用本房显式构图偏移与跟随轴，完整视野仍受roomBounds限制。关闭纵向跟随的房间保留固定高度；开启纵向跟随的房间同时对准Player的纵向目标。镜头Z、正交尺寸与房间显示边界不变。
- 立即定位不经过阻尼，并清空上一目标或移动阶段的平滑速度；后续正常跟随继续使用房间配置的阻尼。
- 移动Entrance-DEFAULT后无需同步移动Main Camera：新生成的Player位置决定相机跟随目标，边界附近允许Player偏离画面中心。此规则同样适用于非DEFAULT入口和复活点。
- 仅Player可作为跟随目标；镜像生成、回收或死亡不得触发相机重新定位。解绑后停止跟随，重新绑定时按新目标与当前房间边界立即定位。
- 历史入口构图字段alignEntryFramingToBounds、entryFramingBounds保留用于旧资产兼容，不再覆盖出生定位。BeginEntryFraming作为旧调用兼容入口执行立即对准，不恢复等待接管行为。
- 固定单屏效果仍由显式相机边界限制完整视野；没有绑定目标的相机维持场景构图。原“等待跨越跟随线”规则及房间文档中的相关历史记录由本节替代。

## 房间边界与停止跟随

每个正式房间必须明确配置相机可显示边界。该边界表示镜头允许显示的最大世界范围，不得根据Tile名称、Tilemap名称、GameObject名称或房间编号推断。

常规跟随镜头遵循以下规则：

- Player位于房间内部时，相机按照常规跟随规则移动。
- 当继续跟随Player会使镜头视野越过房间相机边界时，相机停留在边界位置。
- 相机停止后，Player仍可继续移动，并逐渐从屏幕中央移动到屏幕边缘区域。
- Player从房间边缘返回内部后，相机恢复跟随。
- 恢复跟随不得产生突然跳动、瞬间传送或明显抖动。
- 水平和垂直边界分别判断；触碰一个方向的边界不得阻止另一个方向的合法跟随。
- 相机视野不得显示房间边界之外的空白、未完成地形或相邻房间内容。
- Player、MirrorClone或其他玩法对象不得把镜头拉出当前房间边界。
- 镜头震动和临时表现也不得暴露房间边界之外的区域。

边界限制作用于整个相机视野，而不是相机中心点。

以矩形相机边界为例，相机中心的合法范围为：

- 最小X：房间左边界加相机视野半宽
- 最大X：房间右边界减相机视野半宽
- 最小Y：房间下边界加相机视野半高
- 最大Y：房间上边界减相机视野半高

因此，相机停止时应保证视野边缘与房间相机边界对齐。

如果房间尺寸小于当前完整视野：

- 相机使用固定构图并在对应方向居中显示房间。
- 不得仅为填满屏幕而自动放大镜头。
- Player占屏比例仍应遵循全局镜头规范。
- 房间边界之外的区域必须通过统一的背景延伸或遮挡方式处理，不得暴露未完成内容。

## 镜子与MirrorClone可见性

- 放置镜子前，玩家必须能够观察放置表面及镜像预计出现的主要空间。
- 镜子成功放置后，镜头不得因为生成MirrorClone而突然缩放或跳转。
- 谜题要求同时控制Player与MirrorClone时，镜头应尽量同时显示Player、镜子、MirrorClone及当前受影响的压力板、门、危险或目标。
- 不得将MirrorClone送出可观察区域后要求玩家依靠猜测完成精确操作。
- 如果单一跟随镜头无法清楚呈现上述关系，应调整房间布局、采用固定房间镜头或使用经过批准的通用取景方案，不能在房间脚本中临时改变镜像规则。

## 固定单屏房间

固定单屏镜头允许突破常规角色位置，但必须满足：

- 当前谜题的入口、操作对象、结果对象和主要失败路径同时可见。
- Player占屏高度原则上仍保持在`12%–14%`。
- 房间边界不得出现没有玩法意义的大面积空白。
- HUD不得遮挡出口、危险、压力板、门或镜子放置提示。
- 房间文档必须记录固定镜头尺寸、Player初始构图位置及采用固定镜头的原因。

如果房间确实需要超出常规比例，必须在房间文档中明确记录例外及其玩法理由。

## 死亡、重置和场景切换

- Player死亡重置后，相机必须回到复活位置对应的正确构图。
- Player重置回房间入口时，相机恢复房间配置的入口构图，并重新计算水平、垂直两轴的接管方向；不得保留重置前已经完成的接管状态。
- Player重置到非入口检查点时，相机直接采用检查点对应的常规跟随构图，不要求Player再次穿越原入口的接管线。
- 手动重置和Player死亡重置必须复用当前Player目标；Player传送到复活点并同步物理Transform后，相机清空追赶速度并立即对准。
- 重置不得保留死亡前的追踪偏移、临时缩放或镜头震动。
- MirrorClone死亡或镜子被回收时，不得遗留以已销毁对象为目标的构图状态。
- 场景切换时旧房间相机与旧Player一起销毁；目标房间相机必须先采用目标房间的构图和边界，再绑定新Player并恢复输入，不得短暂显示新房间边界之外或旧房间的位置。
- 镜头表现不得延迟房间重置或改变玩法状态恢复顺序。

## 画面比例适配

- `16:9`是镜头比例和构图验收的基准画面比例。
- 在其他受支持的画面比例下，必须根据实际视野重新计算相机视野半宽和半高，不得直接复用`16:9`的边界钳制结果。
- 画面比例变化不得使Player占屏高度超出常规目标，也不得裁掉当前谜题的关键因果对象。
- 更宽画面可以显示更多横向环境，不得通过额外放大角色抵消新增视野。

## 房间设计要求

每份正式房间文档必须记录：

- 镜头模式：固定单屏或常规跟随
- 是否使用全局默认比例
- 跟随目标与跟随轴
- 显式构图偏移；存在不跟随轴时同时记录该轴的固定相机中心坐标
- 阻尼时间
- 相机可显示边界
- 必须同时进入视野的玩法对象
- 允许的构图边界
- 是否存在经过批准的镜头例外及其理由

房间不得通过修改Player尺寸来满足镜头构图。

## 验收标准

至少在`16:9`画面下验证：

- Player站立时占屏高度为`12%–14%`。
- Player和MirrorClone都能清楚辨认。
- Scene中相机控制器不序列化Player引用，Spawner显式引用本房唯一相机；运行时生成后目标绑定到当前Player而不是旧Scene对象。
- 进入危险前能够观察危险及安全落点。
- 当前谜题的操作对象与结果对象可以建立明确视觉联系。
- 放置、回收及重复尝试镜子时镜头不跳动。
- Player分别走到房间左、右、上、下边缘时，相机在正确位置停止。
- 相机停止后Player仍能正常移动，不会被相机边界改变物理结果。
- Player返回房间内部时相机平滑恢复跟随。
- Player分别从左、右、上、下入口出生时，对应轴在到达目标构图线前保持入口构图，到达后开始跟随；斜向入口的两轴可以独立接管。
- 相机在房间边缘不会显示房间外内容。
- Player死亡、MirrorClone死亡、手动重置和场景切换后构图及相机边界正确。
- 初次进入和重置对准不依赖相机在编辑器中的临时摆放差值，重新绑定目标不继承旧目标偏移或追赶速度。
- 固定单屏房间没有被HUD遮挡的关键玩法对象。
- 在所有受支持的画面比例下重新验证视野边界和关键对象可见性。
