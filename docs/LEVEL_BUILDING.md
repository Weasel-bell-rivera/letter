# 关卡搭建规范

## 基础单位

- 1个标准地形格为1×1 Unity unit。
- 正式房间的静态地面、墙壁和固定平台必须使用标准Grid与Tilemap搭建；现有原型仅可在迁移完成前暂时保留Sprite与独立Collider灰盒。
- Tilemap分层、碰撞、表面语义以及动态玩法对象的职责边界以 `docs/systems/LEVEL_GEOMETRY_SYSTEM.md` 为准。
- 玩家尺寸、跳跃高度和通道宽度必须使用同一套尺度。
- 玩家Collider宽度为：`0.8 Unity unit`。
- 玩家Collider高度为：`1.8 Unity units`。
- Player横向行走与垂直下落通道的最小净空、测量方式和适用范围，以`docs/systems/LEVEL_GEOMETRY_SYSTEM.md`的“Player通道最小净空”为准；本章不另设通道宽高阈值。
- 普通平台的最小站立宽度为：`1.25 Unity units`。
- 标准可靠跳跃距离：`3.5 Unity units`；这是关卡灰盒采用的保守值，不是物理极限值。
- 以完整助跑和标准跳跃计算的理论水平位移约为 `4.2 Unity units`；普通房间必须保留至少 `0.7 unit` 的落地余量。
- 不使用极薄Collider制造不可见障碍。

以上尺寸必须以 `docs/PLAYER_MOVEMENT.md` 中的移动参数和实际 Player Collider 为依据，通过Unity灰盒测试确定，不能仅凭视觉估算。

## 地面

- 地面阻挡玩家和明确配置为需要碰撞的动态物体。
- 地面是否阻挡镜像，以 `docs/COLLISION_RULES.md` 的已确认交互矩阵为准。
- 地面必须提供稳定的落地检测。
- 视觉边界应与Collider边界基本一致。

## 墙壁

- 普通墙壁不可穿越。
- 普通墙壁不能放置镜子。
- 特殊墙面可以根据镜子规则允许放置镜子。
- 特殊墙面必须具有统一的视觉标识和Collider配置。

## 房间通用生成与验收规则

### 适用范围与权威来源

- 本节是所有区域房间共用的生成、手工搭建与增量修改检查清单。新建房间逐项检查；增量修改逐项判断影响范围，并检查受影响对象及其关联入口、路线、机关和镜头，不因局部修改自动重建或重验整个区域。
- 本节集中定义“检查什么”，不复制各系统的数值、碰撞矩阵或生命周期定义。具体规则以表中权威文档及已批准的房间设计为准；发现冲突时先报告，不自行选择新参数或批准例外。
- 检查以实际世界空间的Collider、Trigger、支撑面、交互锚点和相机视野为依据，不能只比较Transform中心、Sprite画布、对象名称或对象数量。
- 本节不要求每个房间必须使用镜像、必须有敌人或必须包含出口。纯教学、过渡房和明确批准的无出口灰盒按各自范围检查；不存在的机制记为“不适用”，不得为满足清单擅自新增内容或连接。

### 通用检查清单

| ID | 检查项 | 要求 | 权威来源 |
|---|---|---|---|
| RV-01 | 入口与复活位置安全 | 检查所有入口和实际复活位置，不只检查DEFAULT。按进入或重置完成后的状态，完整Player Collider不得与地形、关闭的门、危险区、敌人或其他阻挡对象重叠。普通站立出生应有安全支撑；空中进入等特殊方式必须有已批准设计和安全落点。 | `docs/systems/PLAYER_PREFAB.md`、`docs/systems/CHECKPOINT_SYSTEM.md`、`docs/systems/RESET_SYSTEM.md` |
| RV-02 | 出生与出口分离 | 检查Player生成边界与本房所有出口Trigger的关系，默认避免重叠；对应出口及DEFAULT最近出口的优先净距按Player生成文档执行，测量边缘净距而非中心距离。已批准的窄平台、垂直连接或既有布局例外仍必须使用通用出口防回触机制；出生和重置不得立即反向切场，也不得因无法离开释放区而让应可用的出口永久失效。不得缩小Player或出口Trigger规避。 | `docs/systems/PLAYER_PREFAB.md`、`docs/systems/RESET_SYSTEM.md` |
| RV-03 | 通道与运动净空 | 按路线最窄处和完整角色边界检查行走、下落、起跳与落地空间；通道最低净空不等于跳跃可行。使用统一移动参数，不通过房间内缩放角色或覆盖移动参数补救错误布局。 | 本文“基础单位”、`docs/systems/LEVEL_GEOMETRY_SYSTEM.md`、`docs/PLAYER_MOVEMENT.md` |
| RV-04 | 对象支撑与安装 | 需要地面支撑的敌人、压力板等正确贴地；墙装、顶装对象贴合明确安装面。检查实体Collider、Trigger、视觉边界和关键锚点，不得出现未声明的悬空、埋地、穿墙或交互面被遮住。悬浮、嵌入等特殊方式必须已有批准依据。 | `docs/systems/LEVEL_GEOMETRY_SYSTEM.md`及对应对象系统文档 |
| RV-05 | 门洞与阻挡 | 门与对应缺口、墙体网格列对齐；打开后完整通道内无意外残留Terrain，关闭与防夹沿用通用规则。只有被房间设计声明为必经阻挡的门，才额外要求不存在绕过该阻挡的意外路线。 | `docs/systems/DOOR_SYSTEM.md`、`docs/systems/LEVEL_GEOMETRY_SYSTEM.md`及对应房间文档 |
| RV-06 | 出口与连接有效 | 已实现出口必须可实际进入，目标Scene可加载、目标入口存在；双向或分支连接使用正确的来源入口ID，不依赖DEFAULT回退掩盖错误。已实现连接与地图和房间文档一致；规划连接、未启用出口和无出口灰盒分别记录，不擅自补建。 | `docs/maps/MAP.md`、`docs/systems/PLAYER_PREFAB.md`及对应房间文档 |
| RV-07 | 地形与危险一致 | 可站立面、实体碰撞、危险Trigger和可见边界符合显式表面语义。对按规则不提供实体支撑的危险，检查同位置是否误留实体地形；不可一概禁止所有危险与地形重叠。装饰不得暗中承担碰撞、危险或镜面语义。 | `docs/systems/LEVEL_GEOMETRY_SYSTEM.md`、`docs/COLLISION_RULES.md`及对应区域、危险系统文档 |
| RV-08 | 机关引用与作用路径 | 门、开关、敌人、移动对象等引用完整，控制源和目标明确。按设计所需状态检查感应、射线、弹道、移动路径及关键锚点净空；需要畅通的路径不得被无关地形阻断，有意利用遮挡或开关门改变路径的设计按其状态分别检查。 | 对应机关系统文档及房间文档 |
| RV-09 | 镜子与双角色空间 | 要求使用镜子的阶段必须存在可到达的合法放置位置，并满足镜子和预计MirrorClone生成空间要求。双角色路线按共享输入、独立物理和实际姿态检查，不能把两条分别可走的路线当作可同时完成的解法；Player、镜子与MirrorClone允许的重叠保持不变。 | `docs/MIRROR_MECHANIC.md`、`docs/PLAYER_MOVEMENT.md` |
| RV-10 | 镜头与信息可见性 | 初次进入和重置时Player可见；操作前可观察必要的危险与落点，当前需要同时判断的角色、操作对象和结果对象可观察。按实际宽高比与完整视野检查，不要求跟随镜头显示整房，也不能仅凭房间边界坐标判定固定单屏覆盖。 | `docs/systems/CAMERA_SYSTEM.md`、`docs/LEVEL_DESIGN.md` |
| RV-11 | 失败恢复与状态清理 | 失败后可通过已批准的重试或重置路径恢复，不形成出生死亡循环或不可恢复状态。重置按统一顺序恢复临时对象、清理镜像交互占用并保证复活安全；永久状态按规则保留，不把全部机关一律恢复未解锁。 | `docs/systems/RESET_SYSTEM.md`、`docs/systems/SAVE_SYSTEM.md`、`docs/systems/CHECKPOINT_SYSTEM.md` |
| RV-12 | 资产与配置一致 | 正式房间使用统一Player生成系统，入口ID唯一且DEFAULT唯一，Prefab连接和关键引用完整；不覆盖基础角色或镜子规则。Scene与房间文档一致，Builder不得恢复旧坐标或覆盖手工布局；过期Builder只能作为历史入口，未经同步不得用于重建。 | `docs/systems/PLAYER_PREFAB.md`、`docs/systems/LEVEL_GEOMETRY_SYSTEM.md`、`docs/UNITY_MCP_WORKFLOW.md` |

“重叠”必须结合双方交互规则判断：角色进入压力板Trigger、Player与MirrorClone生成重叠等属于合法交互，不能被通用检查器一律判错。静态检查也不得从Tile、Sprite、GameObject名称或房间编号推断规则。

### 检查结果与交付

- 新建房间交付前逐项记录结果；增量修改记录本次影响的检查项，其余注明未受影响且本次未重验，不冒充全房通过。记录可放在对应房间文档或本次任务报告中，不要求为简单修改另建提案。
- 结果分为：**通过**（有对应证据）、**错误**（明确违反已批准规则）、**已批准例外**（引用批准依据并检查必要保护措施）、**待验证**（缺少运行证据或无法静态判断）、**不适用**（说明本房或当前批准范围为何无此要求）。
- 每条错误、例外和待验证项应包含检查ID、Scene、对象或入口ID、相关坐标或边界、原因及证据或缺失的验证内容。例外必须已有批准依据；不能事后把制作错误标为例外。
- 发现明确错误时不得把该房间标为验收通过；已有工作可以保留为未完成灰盒，不得为消除报告而丢弃手工编辑、扩大任务范围或运行旧Builder整房覆盖。
- 静态结构与空间检查优先执行；截图只能证明对应画面状态。真实共享输入、跳跃容错、机关时序、死亡与重置等运行结论需要相应证据；对象数量正确、分别寻路成功或传送角色到机关旁均不能证明完整解法成立。
- 检查清单不自动授权Unity批处理、PlayMode自动测试、完整EditMode测试、完整编译、全量重导入、项目复制、整房重建或人工试玩。始终遵循`AGENTS.md`的范围与确认规则；未执行的验证如实记录，不为追求清单全部通过自行追加耗时操作。
- 本节是制作与验收要求，不表示统一自动验证器已经实现。Builder或检查工具仅能报告实际执行过的检查；尚无自动检查的条目通过直接相关的低成本审查记录，无法证明的部分保留为待验证。

### 与具体谜题验收的边界

通用检查通过只说明房间满足已检查的空间、安全和配置要求，不证明谜题必然可解、核心机制必需或关卡有趣。核心洞察、完成条件、必要机制、逃课边界、时序容错及难度属于对应房间设计；不得把“所有房间必须使用镜像才能通关”加入通用检查。
