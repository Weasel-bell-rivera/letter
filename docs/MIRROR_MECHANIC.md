# 镜子与镜像机制

## 核心设计决策状态

本节记录会直接影响镜像控制、物理结构、碰撞处理和关卡设计的核心决定。已经确认的项目是正式规则；仍标记为“待确定”的项目不得由实现者自行推断。

### 镜像运动模型（已确定）

- 镜像拥有独立的 `Rigidbody2D` 和 `Collider2D`。
- 玩家输入根据镜面位置和朝向进行变换后传递给镜像。
- 镜像独立执行移动、重力和碰撞计算。
- 玩家与镜像可能因为不同的地形和障碍物而失去严格的位置对称关系。
- 镜像生成位置由镜面位置和朝向决定，但生成后不强制保持与玩家严格对称。
- 玩家和镜像被不同地形阻挡时，各自保留独立的物理结果，不强制纠正位置差。

当前决定：**输入变换后独立受物理控制**

选择理由：让玩家和镜像能够面对不同地形、碰撞和机关，从而形成同时控制两个角色的解谜空间。

### 移动平台交互（已确定）

- Player和MirrorClone都可以站在通用移动平台上，并从实际支撑Collider获得同一个世界空间表面速度。
- MirrorClone是否受到平台支撑，按其当前局部重力方向判断；特殊墙面镜生成的旋转重力MirrorClone不把世界坐标下方写死为支撑方向。
- 平台速度只在Player和MirrorClone各自的物理控制中与相对运动合成一次；平台不得直接改写任一角色的位置。
- 平台承载不改变Player或MirrorClone的输入映射、相对移动速度、重力、相对跳跃速度、土狼时间或输入缓冲参数。
- 角色主动移动仍以平台为相对参考；跳起或离开支撑面后不再接收平台后续速度，并保留离开瞬间的世界速度。角色与平台之间不建立父子Transform关系。
- 移动平台属于非静态`DynamicSurface`，不能放置镜子。区域视觉、移动方向和平台当前是否暂停都不改变该规则。
- 具体平台路径、等待、重置和Prefab规则以`docs/systems/MOVING_OBJECTS.md`为准。

### 地面传送带交互（已确定）

- Player和正常重力MirrorClone真正由传送带上表面支撑时，获得完全相同的世界空间表面速度。
- 传送带方向是环境状态，不经过镜面输入变换；地面镜生成的双方受到同一个世界左右方向的速度。
- 特殊墙面镜生成的侧向重力MirrorClone接触水平传送带侧面时，不获得传送带表面速度。
- 表面速度与角色相对传送带的主动移动速度相加，不改变输入映射、基础移动参数、跳跃、土狼时间或输入缓冲。
- 角色跳起或离开传送带时保留离开瞬间世界速度，随后由现有空中控制处理。
- `Conveyor`始终不是合法镜子放置表面；传送带停用时也不改变该规则。
- MirrorClone死亡、镜子回收或镜像清除时，其传送带接触和表面速度状态随对象生命周期立即清除。
- 完整规则见`docs/systems/CONVEYOR_SYSTEM.md`。

### 压沉土块交互（已确定）

- Player与MirrorClone以各自`Rigidbody2D.mass`参与压沉土块承重，身份不改变重量规则。
- 只有角色实际由土块上表面支撑时才计重；特殊墙面镜生成的侧向重力MirrorClone仅接触土块侧面时不计重。
- 土块运动作为安全动态支撑面的世界空间表面速度交给角色，承载规则与通用移动平台一致。
- MirrorClone被回收、死亡或清除后立即解除其承重，不重置整个土块；土块随后按自身规则恢复。
- 压沉土块始终是`DynamicSurface`，不能放置镜子；静止、运动和完全下沉状态均不改变该规则。
- 完整规则见`docs/systems/SINKING_EARTH_BLOCK_SYSTEM.md`。

### 地面弹簧交互（已确定）

- Player和MirrorClone具有完全相同的弹簧触发资格、回弹速度、有效面、重复接触和重置规则。
- 弹簧的顶、左、右外法线属于世界环境方向，不经过镜面输入变换；特殊墙面镜生成的旋转重力MirrorClone仍按实际接触面回弹。
- 顶面目标弹射高度为`5 units`，左右侧面固定回弹速度为`8 units/s`；法向速度被替换，切向世界速度保持不变。
- 弹簧使用显式`Spring`表面语义且不具有`MirrorSurface2D`，因此始终不是合法镜子放置表面。
- 镜子回收、MirrorClone死亡或镜像清除时必须立即清除对应弹簧接触记录，但不重置弹簧或Player。
- 完整规则见`docs/systems/SPRING_SYSTEM.md`。

### 地面镜的物理形态（已确定）

- 镜子底座落在水平地面上，镜面保持竖直。
- 逻辑镜面与视觉镜面的中心和方向必须一致。
- 地面放置时，镜子底座中心位于玩家脚底中心对应的地面点，镜面保持竖直。
- 竖直逻辑镜面的世界坐标 `X` 与放置瞬间Player Collider中心的 `X` 相同。
- 镜子为非实体装置，允许视觉镜体和逻辑镜面与Player或MirrorClone重叠，不产生阻挡或推动。
- 地面镜与角色重叠时使用固定的前后显示顺序：MirrorClone在最后层，Player在中间层，镜子在最前层。
- 镜子处于`Held`或`Unobtained`状态时不显示手持镜或场景镜视觉；只有左键成功放置并进入`Placed`状态后才生成镜子视觉。
- 正式镜子视觉使用`Assets/Art/Kenney/NewPlatformerPack/Sprites/Tiles/Double/Coin/coin_gold_side.png`，保持原始宽高比；可见高度约`0.6 Unity units`，即Player固定`1.8 units`物理高度的约三分之一，地面放置时底部贴合有效表面。
- 镜子成功放置后持续保持可见，直到玩家主动回收、镜像死亡联动、镜子被特定危险破坏、玩家死亡重置或场景切换。

- 放置后不允许单独调整朝向；如需改变放置方向，必须先右键收回，再改变玩家朝向并重新放置。

镜子的实体规则已经确定：

- 镜子不具有阻挡玩家、镜像或动态物体的实体碰撞。
- 玩家和镜像不能把镜子当作可站立平台。
- 镜子作为可见装置、逻辑镜面、回收目标和危险检测对象存在。
- 普通Hazard默认不破坏镜子。只有以后被明确批准并标记为“可破坏镜子”的特定危险，才能通过Trigger或专用交互触发镜子破坏流程；不得从Hazard名称或Layer自行推断。

### 镜子放置目标（已确定）

- 玩家按下鼠标左键时，系统按照固定优先级选择放置目标，不使用鼠标世界坐标选点。
- 第一优先级：如果玩家正面向并紧邻一个允许放置镜子的特殊墙壁，则将镜子放置到该墙壁的有效安装点。
- 第二优先级：如果没有符合条件的特殊墙壁，则尝试在玩家当前脚下的有效地面放置镜子。
- 地面放置时，镜子底座吸附到玩家脚下的有效表面，镜面保持竖直。
- 两种检测均未找到有效表面时，放置失败且不改变当前状态。
- “面向”的判定使用玩家最后一次非零水平输入确定的当前朝向；“紧邻”使用下方已确认的 `0.25 Unity unit` 检测距离。
- 玩家必须处于稳定落地状态才能放置镜子；首版不允许在跳跃、下落或其他空中状态放置，包括特殊墙壁放置。

由于不使用鼠标世界坐标，远程选点和隔墙选点不适用。特殊墙壁检测距离、动态平台、斜坡、危险表面、空间占用和无效反馈规则见下方“放置合法性”。

### 特殊墙壁放置的输入映射（已确定）

所有方向必须使用世界坐标描述：右为 `+X`，左为 `-X`，上为 `+Y`，下为 `-Y`。

| 特殊墙壁位置 | 玩家向右输入映射为 | 玩家向左输入映射为 | 玩家跳跃映射为 |
|---|---|---|---|
| 墙在玩家左侧，可放置面朝右 | 镜像向上 | 镜像向下 | 镜像向左 |
| 墙在玩家右侧，可放置面朝左 | 镜像向下 | 镜像向上 | 镜像向右 |

正式规则：

- 左右两侧的特殊垂直墙壁都允许放置镜子。
- 输入映射由墙面法线和统一的正负90度坐标旋转计算。
- 不得在具体房间脚本中单独指定方向。
- 持续按键、松开按键和反向输入沿用玩家控制器的加速、减速和输入释放规则，只对方向向量做旋转。
- 镜像的重力、落地检测、最大下落速度和跳跃方向与移动输入一起旋转，形成统一的局部物理空间。
- 镜像的跳跃方向始终与其局部重力相反，使用与Player相同的跳跃高度和到达最高点时间。
- `Jump`的按下、持续和松开属于原始共享输入，同时传给Player和MirrorClone；不是在Player成功起跳后才通知MirrorClone。
- Player和MirrorClone分别使用自身的落地检测、土狼时间、输入缓冲和局部重力判断能否起跳。一方未成功起跳不得阻止另一方起跳。

### 已放置镜子时再次放置（已确定）

- 场景中已有镜子时，再次按下左键操作无效。
- 现有镜子和镜像保持不变。
- 玩家必须先按鼠标右键收回镜子，才能重新放置。
- 无效操作不得改变镜像、机关、触发器或房间状态。

再次左键时显示约 `0.15` 秒的红色无效轮廓，并播放轻微失败音效；不显示文字提示。

### 放置合法性（首版已确定）

地形可以由`TilemapCollider2D`或独立`Collider2D`提供。两种实现必须通过统一表面查询返回放置点、表面法线、表面类型和安全状态，并产生完全一致的放置结果。Tilemap分层与表面语义的技术规范见`docs/systems/LEVEL_GEOMETRY_SYSTEM.md`。

- 镜子系统不得根据Tile名称、Sprite名称、GameObject名称、具体Tilemap名称或房间编号判断放置合法性。
- 使用Tilemap不得新增、删除或改变任何已确认的镜子放置表面。
- 新增表面类型或运行时地形变化影响镜子时，必须先更新本文档和相关测试。

| 规则 | 当前决定 |
|---|---|
| 特殊墙壁最大检测距离 | 从玩家Collider边缘沿面朝方向检测 `0.25 Unity unit` |
| 玩家与特殊墙壁之间是否必须无遮挡 | 必须无遮挡 |
| 是否允许隔墙放置 | 不允许；不使用远程选点 |
| 镜子所需最小空间 | 镜子的完整逻辑边界不得与墙壁、门或其他实体Collider重叠 |
| 是否允许与玩家或镜像重叠 | 允许；地面放置的左右生成与特殊墙壁放置的上下生成都允许MirrorClone与对应Player位置及Collider重叠，双方无实体碰撞 |
| 是否允许放在动态平台上 | 首版不允许 |
| 是否允许放在地面传送带上 | 不允许；启用和停用状态均不允许 |
| 是否允许放在斜坡上 | 首版不允许 |
| 是否允许放在危险表面上 | 不允许 |
| 是否允许放在可破坏表面上 | 首版不允许 |

放置检测必须在生成镜子和镜像之前完成：

- 首版只允许静态、平坦、安全、不可破坏的水平地面，以及明确标记的特殊垂直墙壁。
- 镜像的预计生成位置必须能够容纳完整的 `MirrorClone` Collider。
- 地面放置和特殊墙壁放置时，镜像生成空间与对应Player部分或完全重叠都属于正式规则，不导致放置失败。
- 除对应Player外，镜像生成空间被其他角色、墙壁、门或其他实体Collider占用时，放置失败。
- 放置失败时不得改变镜子、镜像、Trigger或机关状态。
- 放置失败时显示约 `0.15` 秒的红色无效轮廓，并播放轻微失败音效；不显示文字提示。

## 基本操作

- 镜子能力尚未解锁时，玩家不持有镜子，放置和收回输入均无效，也不会生成MirrorClone。
- 镜子能力在`CENTER_001`通过永久拾取解锁；获得与持久化规则见`docs/rooms/center/CENTER_001.md`和`docs/systems/COLLECTIBLE_SYSTEM.md`。
- 鼠标左键：在有效位置放置镜子。
- 镜子成功放置后，立即显示场景镜并生成镜像角色；放置失败时镜子仍保持隐藏。
- 鼠标右键：收回已经放置的镜子。
- 镜子被收回时，对应的镜像角色立即消失。
- 场景中同时最多存在一面镜子和一个镜像角色。
- 除暂停、玩家死亡重置和场景切换已接管输入的状态外，只要镜子已经放置，右键回收就在当前固定帧拥有最高玩法处理优先级；镜像处于移动、跳跃、下落、危险区、Trigger或压力板中都不能阻止回收。
- 回收必须先清除镜像及其全部Trigger、压力板和事件占用，再结算该固定帧后续的危险与机关状态；回收没有冷却，完成后可以再次放置。

## 状态变化

未放置镜子：

- 镜子由玩家逻辑持有，但不显示手持镜视觉
- 镜像角色不存在

上述“未放置”状态只适用于已经永久解锁镜子能力的Player。尚未解锁时使用独立的“未获得”状态：镜子不在Player手中，镜像角色不存在。

放置镜子后：

- 镜子位于场景中
- 镜像角色存在

收回镜子后：

- 镜子回到玩家逻辑持有状态，场景镜视觉立即隐藏且不显示手持镜视觉
- 镜像角色消失

## 死亡、破坏与三者联动（已确定）

### 玩家死亡

- 镜像立即消失。
- 镜子立即回到玩家手中。
- 立即进入房间死亡重置流程。
- 镜像消失时必须先清理所有Trigger、压力板和事件占用。

### 镜像死亡

- 镜像立即消失，玩家不死亡。
- 镜子自动回到玩家手中。
- 不会自动生成新镜像。
- 玩家必须再次按左键成功放置镜子，才能生成新镜像。

### 镜子被危险破坏

- 镜像立即消失，玩家不死亡。
- 镜子立即回到玩家手中。
- 玩家可以再次尝试放置镜子。
- 镜子回收立即完成，不设置冷却时间。

### 联动不变量

- 不允许出现“镜子仍在场景中，但对应镜像已经死亡或消失”的残留状态。
- 不允许出现镜像存在但没有对应镜子的状态。
- 镜像死亡或镜子被破坏不会直接重置整个房间；只有玩家死亡进入死亡重置流程。
- 所有联动必须在同一个确定性的生命周期流程中完成，避免机关短暂保持错误状态。

房间和场景的整体恢复规则见 `docs/systems/RESET_SYSTEM.md`。


## 镜子放置表面

### 普通地面

- 默认情况下，镜子只能放置在水平地面上。
- 普通墙面、天花板和其他垂直表面不允许放置镜子。
- 镜子放置成功后，其镜面方向由地面朝向决定。
- 镜像角色按照镜子的反射规则生成。

### 寒冰地面与冻结敌人（已确定）

- 带`FrozenGround`表面语义的静态、水平、安全寒冰地面，在满足通用空间条件时允许放置镜子。
- 移动中的Player稳定踩入`FrozenGround`后在首次接触格内逐渐冻结，到格中心按Player死亡处理：清除MirrorClone、回收镜子并执行完整房间重置，返回当前出生点或复活点。
- MirrorClone不受上述`FrozenGround`死亡规则影响，仍使用已批准的低摩擦滑行；`FreezingGround`对MirrorClone的冻结死亡规则保持不变。
- 镜子成功放置后保持固定，不受寒冰低摩擦效果影响。
- 寒冰地面上的镜像生成空间仍须通过完整合法性检查。
- 只有寒冰外观但不带`FrozenGround`语义的装饰不得影响镜子放置结果。
- 寒冰墙壁不是特殊镜墙，不能仅因具有寒冰外观而安装镜子。
- 活动敌人、冻结敌人和移动寒冰平台都属于动态对象或动态表面，不能放置镜子。
- 活动敌人和冻结敌人默认不破坏镜子。

雪区寒冰与敌人规则分别见`docs/regions/SNOW_REGION.md`和`docs/systems/ENEMY_SYSTEM.md`。

### 冻结地面（已确定）

- `FreezingGround`是独立于`FrozenGround`的雪区静态表面语义。
- Player与MirrorClone使用完全相同的接触、冻结累积、空中保持、普通地面恢复、目标格锁定和运动减速规则。
- MirrorClone的局部运动与重力方向不改变冻结累积速率；完全冻结时沿所接触冻结表面的切线对齐到首次接触格中心。
- MirrorClone完全冻结按镜像死亡处理：立即清理Trigger、压力板和事件占用，销毁镜像并自动回收镜子；Player和房间不整体重置。
- Player完全冻结按Player死亡处理：先清除MirrorClone并回收镜子，再执行完整房间重置。
- 镜子本体不累积冻结；静态、水平、安全且空间充足的`FreezingGround`允许放置镜子，放置后镜子保持固定。
- `FreezingGround`上的镜像生成空间仍须通过通用合法性检查；冻结Enemy和其他动态对象仍不能作为镜子放置表面。

### 雪区周期落雪与雪人道具（已确定）

- 周期落雪危险阶段命中MirrorClone时沿用镜像死亡规则：立即清理交互占用、销毁镜像并自动回收镜子，不重置Player、Enemy或落雪周期。
- 周期落雪命中Player时沿用Player死亡与完整房间重置规则。
- 落雪不破坏或推动镜子，也不修改镜子放置表面。
- 雪区临时胡萝卜只有Player可以拾取；MirrorClone接触胡萝卜或雪人不会改变道具与挡路状态。

### 特殊墙壁放置（姿态已确定）

区域使用边界：`SpecialMirrorWall`当前只用于风区。雪区房间不得配置特殊墙面镜；寒冰墙壁或雪区装饰墙也不能因此获得墙镜语义。

部分关卡包含具有特殊性质的垂直墙面。

- 镜子可以放置在标记为“可放置镜子”的特殊墙面上。
- 普通垂直墙面仍然不能放置镜子。
- 镜子的安装点附着在特殊墙面上，镜体从墙面垂直伸出。
- 在2D逻辑中，特殊墙壁为竖直方向时，伸出的镜体为水平方向。
- 特殊墙壁放置相对于地面放置使镜子的整体姿态旋转90度。
- 视觉镜体、逻辑镜面和用于输入变换的方向必须保持一致。
- 镜像角色沿镜面法线方向生成，使玩家与镜像形成垂直方向上的空间关系。
- 特殊墙面必须具有清晰且统一的视觉标识。
- 玩家在尝试放置前，应当能够判断该墙面是否支持镜子。
- 玩家必须面向并紧邻特殊墙壁，左键才会优先选择墙壁安装点。
- 不满足墙壁放置条件时，左键继续尝试玩家脚下的地面放置，不会吸附到远处墙壁。
- 左右两侧的特殊垂直墙壁均可作为有效安装表面。
- 镜子的水平逻辑镜面安装在玩家脚底高度。
- 生成瞬间，Player位于水平逻辑镜面上方，MirrorClone生成在镜面下方，二者的Collider中心到镜面的距离相等。
- 镜像生成位置允许与对应Player部分或完全重叠；只有被墙壁、门、其他角色或其他实体Collider占用时，特殊墙壁放置才失败。


## 镜像生成方向

镜像生成方向由镜子所在表面的法线决定。

- 镜子放在水平地面时，生成瞬间镜像与玩家关于竖直逻辑镜面形成左右方向的几何对称关系。
- 镜子放在特殊垂直墙面时，镜体水平伸出；生成瞬间，镜像与玩家关于该水平逻辑镜面形成上下方向的几何对称关系。
- 镜子的反射计算不应针对具体关卡写死。
- 地面放置与特殊墙壁放置必须使用同一套基于镜面位置和朝向的变换规则。
- 几何对称只用于确定镜像的初始生成位置。生成后镜像独立受物理控制，不要求持续保持与玩家对称。
- MirrorClone使用与Player相同的Collider尺寸和运动参数；差异只来自输入、重力和局部物理方向的镜面变换，以及已批准的区域效果。
- MirrorClone的视觉尺寸、Pivot、Sprite轮廓和动画必须与Player一致；只能通过已批准的透明度、颜色、材质或特效区分身份，不得使用不同的基础缩放改变角色大小。
- MirrorClone生成瞬间的视觉朝向与Player做水平镜像，因此二者初始面向相反。
- 生成后MirrorClone根据自身经过映射的实际移动方向更新视觉朝向，不再强制复制或持续反射Player的朝向。

### 地面放置的生成与输入映射（已确定）

- 镜子底座中心放在玩家脚底中心对应的有效地面点，竖直逻辑镜面穿过放置瞬间的Player Collider中心。
- 按几何反射计算，Player中心位于逻辑镜面上，因此MirrorClone生成在与Player完全相同的世界位置和姿态。
- 生成瞬间Player与MirrorClone的Collider允许完全重叠；两者之间禁用实体碰撞，因此不会互相阻挡或推动。
- 生成重叠期间采用MirrorClone后层、Player中层、镜子前层的显示顺序；镜子不会因二者离开初始位置而隐藏。
- 生成后双方立即按各自输入映射和独立物理结果运动，不强制继续重叠或保持位置对称。
- 玩家向右输入映射为镜像向左输入。
- 玩家向左输入映射为镜像向右输入。
- Jump原始输入同时交给双方独立判定；地面模式下MirrorClone成功跳跃时方向为正常向上。
- 生成前仍须验证镜子逻辑边界以及除Player之外的镜像生成空间满足放置合法性规则。

### 特殊墙壁放置的方向转换

当镜子放置在特殊垂直墙面上时：

- 镜像的运动空间相对于玩家旋转90度。
- 玩家的水平输入映射为镜像的垂直输入。
- 墙在玩家左侧时，玩家向右映射为镜像向上，跳跃映射为镜像向左。
- 墙在玩家右侧时，玩家向右映射为镜像向下，跳跃映射为镜像向右。
- 反向移动输入产生对应的反向映射。
- 具体方向由墙面法线决定，而不是由关卡脚本单独指定。
- 局部重力、落地检测、最大下落方向和跳跃方向使用相同的正负90度旋转；跳跃始终与局部重力相反。
